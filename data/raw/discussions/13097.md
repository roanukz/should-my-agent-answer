### Description

I am trying to undertand the memory usage of a bigger fastapi application. I'm therefore trying to understand the dependency injection behavior and design.
* The injected object is instantiated on request as documented. However the object is deleted only when the next request using this dependency comes in. This doesn't change wether `use_cache` is `True` or `False`. Is that intentional behavior?
* Dependency injections seems to work on routes only - not on functions that are called by a route. What is the purpose of the cache parameter when the dependency has to passed around manually anyway?

## Accepted answer by sehraramiz (NONE)

according to [this part of the docs](https://fastapi.tiangolo.com/tutorial/dependencies/sub-dependencies/?h=use_cache#using-the-same-dependency-multiple-times):

> If one of your dependencies is declared multiple times for the same path operation, for example, multiple dependencies have a common sub-dependency, FastAPI will know to call that sub-dependency only once per request.
And it will save the returned value in a "cache" and pass it to all the "dependants" that need it in that specific request, instead of calling the dependency multiple times for the same request.

the dependency cache is for the time your dependencies gets multi layered and some dependencies get repeated in the hierarchy, in those cases fastapi caches a dependency when resolved and reuse it if another sub-dependency needs it (if use_cache is True)

so in your example say we have another dependency which also depend on A:

```python
import logging
from typing import Annotated
from fastapi import Depends, FastAPI


app = FastAPI()
log = logging.getLogger(__name__)
logging.basicConfig(level=logging.DEBUG)


class A:
    def __init__(self):
        log.debug("A __init__")

    def __del__(self):
        log.debug("A __del__")


AA = Annotated[A, Depends(A, use_cache=True)]


def another_dependency(a: AA) -> int:
    logging.debug(f"Another dep {a}")
    return 0


@app.get("/")
async def root(a: AA, other: Annotated[int, Depends(another_dependency)]):
    # res = await a_function()
    # dependency injection seems to work on routes only
    res = await a_function(a)

    return res


async def a_function(a: AA):
    log.debug(f"a_function {a}")
    return {"Hello": f"{a}"}


@app.get("/foo")
async def foo():
    return {"Hello": "Foo"}


```

with cache:
```
DEBUG:app:A __init__
DEBUG:root:Another dep <app.A object at 0x726db7767680>
DEBUG:app:a_function <app.A object at 0x726db7767680>
```

without cache:
```
DEBUG:app:A __init__
DEBUG:app:A __init__
DEBUG:root:Another dep <app.A object at 0x7c7e6df65280>
DEBUG:app:a_function <app.A object at 0x7c7e6df66a80>
```

so without cache we instantiated "A" twice and got two unique objects.

and about your second question, yes dependency injection in fastapi only happens in the arguments passed to route definitions and also in path operation decorators. so a_function is just a normal function with some arguments and the Depends part of it is not important until we use this function in a fastapi route or in a fastapi route path operation, then the Depends part of it becomes important.
