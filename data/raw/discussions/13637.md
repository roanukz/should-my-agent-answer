### Description

when theres a GET route that ends in a path variable and a post to a route that matches the get but with a fixed word in then it results in method not allowed 405.

@app.get("/test/{item_id}") 
@app.post("/test/test") 

doing a post to /test/test works fine
doing a post to /test/doesntexist returns method not allowed. 

i know its looking at the get route to match but obviously since its a post it throws the method not allowed error. 

shouldnt this rather throw a 404? 

would the only way around it be to create a "fake" post route that raises a 404? ie

```python
@app.post("/test/test")
def read_item():
    return {"post": "q"}

@app.get("/test/{item_id}")
def read_root():
    return {"Hello": "World"}

@app.post("/test/{item_id}", status_code=404, include_in_schema=False)
def faker_post_path():
    raise HTTPException(status_code=404, detail="Path not found")
```

## Accepted answer by YuriiMotov (MEMBER)

I think returning "method not allowed 405" is correct. The path (resource) is valid (exists), but it just doesn't support the method (operation) that is requested.

Another way to achieve the behavior you want is to add `exception_handler` for status code 405:

```python
from fastapi import FastAPI
from fastapi.responses import JSONResponse

app = FastAPI()

@app.post("/test/test")
def read_item():
    return {"post": "q"}

@app.get("/test/{item_id}")
def read_root():
    return {"Hello": "World"}


@app.exception_handler(405)
def code_405_handler(request, exc):
    return JSONResponse(
        status_code=404,
        content={"detail": "Path not found"},
    )
```

This will turn all `405` responses into `404`
