### Example Code

```python
I have this annoying situation where I have to handle a lot of exceptions with the same handler. An extra *args coud be added in the exception_handler method in order to be able to do something like this:


@app.exception_handler(UserNotFound, AccountNotFound, EmailNotFound, SessionNotFound)
async def handle_not_found(request, exc):
    return HTTPException(
        status_code=status.HTTP_404_NOT_FOUND,
        detail=str(exc)
    )

@app.exception_handler(EmailAlreadyExists, UserAlreadyExists)
async def email_already_exists(request, exc):
    return HTTPException(
        status_code=status.HTTP_409_CONFLICT,
        detail=str(exc)
    )

Instead of writting a handler for every single exception type or status code. It doesn't break backward compatiblity.
```


### Description

In the exception handler: 

```python
    def exception_handler(
        self,
        exc_class_or_status_code: Annotated[
            Union[int, Type[Exception]],
            Doc(
                """
                The Exception class this would handle, or a status code.
                """
            ),
        ],
        *extra_exc_classes_or_status_codes: Annotated[
            Union[int, Type[Exception]],
            Doc(
                """
                Extra Exception classs this would handle, or a status codes.
                """
            ),
        ],
    ) -> Callable[[DecoratedCallable], DecoratedCallable]:
```
Extra attributes could be added. And they can be be implemented simply like this:

```python
    def decorator(func: DecoratedCallable) -> DecoratedCallable:
        self.add_exception_handler(exc_class_or_status_code, func)
        for extra_exc_class_or_status_code in extra_exc_classes_or_status_codes:
            self.add_exception_handler(extra_exc_class_or_status_code , func)
        return func
```
An that's it. Doesn't break barckard compatibility, or add any complexity.

## Accepted answer by YuriiMotov (MEMBER)

PRs:
* #13241 - approach described here
* #13614 - alternative approach

Right now you can use the following approach:
```
@app.exception_handler(EmailAlreadyExists)
@app.exception_handler(UserAlreadyExists)
async def email_already_exists(request, exc):
    return HTTPException(
        status_code=status.HTTP_409_CONFLICT,
        detail=str(exc)
    )
```
