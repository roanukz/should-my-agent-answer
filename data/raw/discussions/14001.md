### Example Code

```python
from fastapi import FastAPI, Request
from fastapi.responses import StreamingResponse
from contextlib import asynccontextmanager
import asyncio, json, time

@asynccontextmanager
async def lifespan(app: FastAPI):
    print("startup")
    yield
    print("shutdown")  # <-- this is never called if SSE is connected

app = FastAPI(lifespan=lifespan)

@app.get("/sse/{uuid}")
async def sse(uuid: str, request: Request):
    async def generate():
        try:
            while not request.is_disconnected():
                yield f"data: {json.dumps({'uuid': uuid, 'ts': time.time()})}\n\n"
                await asyncio.sleep(1)
        except asyncio.CancelledError:
            print(f"SSE {uuid} cancelled")
            raise
        finally:
            print(f"SSE {uuid} closed")

    return StreamingResponse(generate(), media_type="text/event-stream")
```


### Description

Hi, I’m using FastAPI with a StreamingResponse endpoint for Server-Sent Events (SSE).
Everything works fine while the client is connected.

But when I press Ctrl+C to stop the server, if there’s still an active SSE connection, the application does not trigger the lifespan shutdown.

## Accepted answer by XieJiSS (NONE)

Assuming that you are using uvicorn - I believe this is the expected graceful shutdown behavior. Graceful shutdown means to stop the server only when it is safe to do so, i.e., when all active connections are closed. Say, you are downloading a 1MB file via plain HTTP protocol at the speed of 1KB/s from the server. Uvicorn will have to wait for 1000 seconds before it can quit gracefully.

If you really can't change your application logic to avoid long connections, consider passing the `timeout_graceful_shutdown` argument to uvicorn to set a hard limit. Note that this will break the gracefulness and may cause some connections to be interrupted.
