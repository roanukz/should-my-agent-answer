### Description

I am using the following code snippet in my project to validate input and add a description and example in the OpenAPI schema:  

```python
Annotated[
    str,
    Query(
        annotation=Annotated[list[str], AfterValidator(validator)],
        description="Sample desc",
        example="input-string",
    ),
]
```

Here, I use `Query` to validate the input, and since `Query` appears to inherit from `FieldInfo` in Pydantic, I tried using the `annotation` parameter to pass a validator, hoping it would be processed correctly by Pydantic's validation mechanism.  

However, on **March 27, 2025**, Pydantic released version **2.11**, which caused the previously functioning validator to be ignored entirely.  

It seems that there was a fix in #13440, but that addressed Pydantic version **2.10** and was already resolved in **FastAPI 0.115.11**.  

**Expected Behavior:**  
The `annotation` parameter of `Query` should be able to pass the validator, allowing proper validation.  

**Actual Behavior:**  
The validator gets ignored, and the input does not undergo the expected validation.

## Accepted answer by yauhen-sobaleu (NONE)

Define validated type separately and use it with `Query` in the function parameters

```python
from typing import Annotated
from fastapi import FastAPI, Query
from pydantic import AfterValidator

app = FastAPI()

def validator(o: str) -> list[str]:
    print("Do validation for ", o)
    return [o]

# Define the validated type
ValidatedStrList = Annotated[list[str], AfterValidator(validator)]

@app.get("/")
async def root(
    s: Annotated[ValidatedStrList, Query(description="Sample desc", example="input-string")],
    t: Annotated[ValidatedStrList, Query(description="Sample desc", example="input-string")]
):
    return {"message": "Hello World"}
```
