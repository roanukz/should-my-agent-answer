### Description

There appear to be two ways to define Fields (like Query) in FastAPI: using the annotated method or the default value:

https://docs.pydantic.dev/latest/concepts/fields/#the-annotated-pattern
https://fastapi.tiangolo.com/tutorial/query-params-str-validations/

```py

# Option 1
from typing import Annotated
from pydantic import BaseModel, Field


class Model(BaseModel):
    int_list: list[Annotated[int, Field(gt=0)]]


# Option 2
class Model(BaseModel):
    int_list: list[int] = Field(gt=0)
```

In the query docs, [it is recommended to use Option 1, the Annotated type](https://fastapi.tiangolo.com/tutorial/query-params-str-validations/#advantages-of-annotated), for various reasons. However, the Field docs don't mention this advantage at all, and both the default example and the "non-Annotated" variant use the same pattern of Option 2.

Is it preferable to use Annotated for Body Fields, just like it is recommended for Query parameters?

If so - should we update the Body Field documentation to reflect that?
If not - should we at least document both variations in the Body Field docs?

## Accepted answer by alv2017 (CONTRIBUTOR)

> Is it preferable to use Annotated for Body Fields, just like it is recommended for Query parameters?

No, Pydantic supports the use Annotated Fields, but it doesn't claim that it is a recommended approach. (There are pros and cons, and developers are free to choose what works best for them)

> If so - should we update the Body Field documentation to reflect that?

I don't think so

> If not - should we at least document both variations in the Body Field docs?

I don't think so, this is rather about how to use Pydantic (and not the FastAPI). The best way to learn about Pydantic features is to consult the Pydantic documentation.

(imho)
