### Example Code

```python
from fastapi import FastAPI

app = FastAPI()


@app.get("/", response_class=PlainTextResponse)
async def root(encoded_url: str):
    encoded_url  # Already decoded.
    qp = request.scope['query_string'].decode()  # This gives me raw query params but I have to split them myself.
    return encoded_url

# example values to pass to API
# lol%20hi
# https%3A%2F%2Fexample.com
```


### Description

Some context is given in example code.

The problem is that `encoded_url` is automatically URL/percent decoded when it enters the function. Problems: 
* this behavior is not documented anywhere;
* there is no easy way to turn it off or get encoded URL in alternative way;
    * moreover alternative way is very tedious and also undocumented, searching for `fastapi "scope['query_string'].decode()"` in Google gives unrelated results to my question or this behavior (I got the info about the alternative from ChatGPT).

The only thing I've found on the topic is this Issue https://github.com/fastapi/fastapi/issues/4390 but it's related to path arguments not query params. It is mentioned there that the problem may be in Starlette https://github.com/encode/starlette/discussions/1827 but I lost patience to dig further.
I know enough to point out that this behavior isn't documented and tedious to avoid.

## Accepted answer by YuriiMotov (MEMBER)

I think this behavior is absolutely expected. AFAIK, all frameworks work this way.
And I believe in most cases people expect exactly this behavior (nobody wants to decode every value before using it).

If you need encoded value, you can just encode it back or use `request.scope['query_string'].decode()`
