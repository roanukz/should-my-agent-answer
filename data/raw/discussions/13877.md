### Example Code

```python
from enum import StrEnum
from typing import Annotated

from fastapi import FastAPI, Query
from pydantic import BaseModel, BeforeValidator

app = FastAPI()


class Order(StrEnum):
    ASC = "asc"
    DESC = "desc"


class Sorting(BaseModel):
    field: str
    order: Order


def _validate_sorting(raw_sorting: str) -> Sorting:
    field, order = raw_sorting.split(':')

    return Sorting.model_validate(field=field, order=order)


class Pool(BaseModel):
    name: str
    volume: int


@app.get("/pools")
async def get_pools(
    sorting: Annotated[
        Sorting,
        BeforeValidator(func=_validate_sorting, json_schema_input_type=str),
        Query()
    ] = Sorting(field="volume", order=Order.ASC),
) -> list[Pool]:
    pools = [Pool(name="small_pool", volume=10), Pool(name="big_pool", volume=20)]

    return sorted(pools, key=sorting.field, reverse=sorting.order == Order.DESC)
```


### Description

In the [FastAPI tutorial](https://fastapi.tiangolo.com/tutorial/query-params-str-validations/#custom-validation), there is a mention of using functional validators—specifically AfterValidator and BeforeValidator. The usage of AfterValidator is straightforward, but the purpose and behavior of BeforeValidator in FastAPI are less clear.

In Pydantic, BeforeValidator can be used to coerce or cast an input type into a different output type. For this purpose, it provides the json_schema_input_type parameter. This could theoretically be leveraged in FastAPI like so:
```python
@app.get("/pools")
async def get_pools(
    sorting: Annotated[
        Sorting,
        BeforeValidator(func=_validate_sorting, json_schema_input_type=str),
        Query(),
    ] = Sorting(field="volume", order=Order.ASC),
) -> list[Pool]:
...
```
In this case, the idea is to expose the parameter as a string in Swagger (via json_schema_input_type) while internally validating and converting it into a Sorting object. However, this doesn’t seem to work. Instead it shows this:
<img width="584" alt="image" src="https://github.com/user-attachments/assets/3590d74a-a4c7-4cfb-b124-5a3c1d79c3ac" />

I understand that similar behavior can be achieved using Depends to handle custom parsing and validation. But if that’s the case, are there any practical use cases for using BeforeValidator directly in FastAPI routes?

## Accepted answer by YuriiMotov (MEMBER)

Yes, FastAPI is quite straightforward here. If the type of parameter is Pydantic model and it's annotated with `Query`, it treats every field of that model as separate query parameter.
I think we should consider this as a limitation.

I think something like the code below should work for you:

```python
from enum import StrEnum
from typing import Annotated

from fastapi import Depends, FastAPI
from pydantic import BaseModel, BeforeValidator
from pydantic.json_schema import SkipJsonSchema

app = FastAPI()


class Order(StrEnum):
    ASC = "asc"
    DESC = "desc"


class Sorting(BaseModel):
    field: str
    order: Order


class Pool(BaseModel):
    name: str
    volume: int


def _validate_sorting(raw_sorting: str) -> Sorting:
    field, order = raw_sorting.split(":")
    return Sorting(field=field, order=order)


async def get_sorting(
    sorting: Annotated[
        str | SkipJsonSchema[Sorting], BeforeValidator(_validate_sorting)
    ],
) -> Sorting:
    assert isinstance(sorting, Sorting)
    return sorting


@app.get("/pools")
async def get_pools(
    sorting: Annotated[Sorting, Depends(get_sorting)] = Sorting(
        field="volume", order=Order.ASC
    ),
) -> list[Pool]:
    pools = [Pool(name="small_pool", volume=10), Pool(name="big_pool", volume=20)]
    return sorted(
        pools,
        key=lambda x: getattr(x, sorting.field),
        reverse=(sorting.order == Order.DESC),
    )
```

You can get rid of `get_sorting` dependency, but you will have to check the type of `sorting` in your endpoint with `isinstance(sorting, Sorting)` then
