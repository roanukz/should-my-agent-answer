### Example Code

```python
from fastapi import FastAPI
from fastapi.testclient import TestClient
from pydantic import BaseModel, Field
from typing import Generic, TypeVar

T = TypeVar('T')

def timestamp() -> int:
    return 1735326936124

class Response(BaseModel, Generic[T]):
    data: T
    timestamp: int = Field(default_factory=timestamp)

class Model(BaseModel):
    name: str
    sth_else: str | None = Field(None)

app = FastAPI()

@app.get( "/", response_model=Response[Model], response_model_exclude_unset=True)
async def route():
    return Response(data={"name": "test"})

# test case:

def client():
    with TestClient(app) as client:
        yield client

client = TestClient(app)

def test_response():
    response = client.get("/")
    assert response.status_code == 200
    assert response.json() == {"data": {"name": "test"}, "timestamp": 1735326936124}
```


### Description

With the above code I expect the timestamp field to get populated so the response to `/` would look like this: 

```json
{"data":{"name":"test"}, "timestamp":1735326936124}
```

but instead it is ignored:

```json
{"data":{"name":"test"}}
```

It works fine if I remove `response_model_exclude_unset=True` but I don't want to show `sth_else` as `null`, so I need this set!

I checked via `breakpoint` - the default_factory is actually executed, but the result not used in the response?

This used to work - I am not sure what changed?

Maybe someone can point me at what changed and I need to fix?

## Accepted answer by luzzodev (CONTRIBUTOR)

Hello @jkittner,

the option `response_model_exclude_unset` will exclude all fields that are not explicitly set. Using default or default_factory is not considered an explicit set. In your case you can use exclude_none instead of exclude_unset.
