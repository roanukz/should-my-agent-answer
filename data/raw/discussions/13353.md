### Example Code

```python
from typing import Annotated
import time
import threading

from fastapi import FastAPI,Depends

app = FastAPI()
class GlobalCounter:
    def __init__(self):
        self._count = 0

    def increment(self):
        current = self._count
        time.sleep(0.001)  # artificial delay
        self._count = current + 1

    def get_count(self):
        return self._count

counter = GlobalCounter()
lock = threading.Lock()
def get_counter():
    with lock:
        yield counter

@app.get("/increment")
def increment_dep(c: Annotated[int,Depends(get_counter)]) -> None:
    c.increment()
    print(counter.get_count())


# and run  apache bench
# ab -n 2000 -c 100 http://127.0.0.1:8000/increment_dep
```


### Description

Deadlock when the concurrency is above 40, and ONLY when the get_counter is a Depends.

If you manually create and use a context manager, it does not lock up.

```
@contextlib.contextmanager
def get_counter2():
    with lock:
        yield counter
        
 @app.get("/increment_dep2")
def increment_dep2() -> None:
    with get_counter2() as c:
        c.increment()
    print(counter.get_count())
```

```
ab -n 2000 -c 100 http://127.0.0.1:8000/increment_dep2
```

## Accepted answer by luzzodev (CONTRIBUTOR)

Hello @y2kbugger i'll try to explain what is wrong in your code and what is happening.

The problem with your code is that the deadlock happens due to thread exhaustion.

Basically the depency `c: Annotated[GlobalCounter, Depends(get_counter)` is the one that is exhausting the threadpool due the lock and since your endpoint function is sync ( so need a thread ), at some point you will not have any available thread to execute it and since you cannot execute it your dependency will never be released and with that the lock.

A short simple example: suppose to limit the pool to 2 threads and the are 3 incoming requests.

r1 -> solve dependency and lock
r2 -> trying solve dependecy and is wait for the lock
r3 -> is waiting for a thread

r1 with the dependecy solved, now try to call the endpoint function but is sync so need a thread where can be executed but there are no thread available. Here all is blocked forever.

In your second example where you have all inside the endpoint all works because only the endpoint thread is required and you are already inside it.

To fix the first example, just trasform 

`def increment_dep(c: Annotated[GlobalCounter, Depends(get_counter)]) -> None:`
in 
`async def increment_dep(c: Annotated[GlobalCounter, Depends(get_counter)]) -> None:`


In general i would suggest to avoid locks inside the dependency, because you are basically serializing the requests and bringing complexity with it.
