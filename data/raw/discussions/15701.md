### Example Code

```python
from typing import Annotated, Literal

from fastapi import Body, FastAPI
from pydantic import BaseModel, Field
from typing_extensions import TypeAliasType


class Cat(BaseModel):
    pet_type: Literal["cat"]
    meows: int


class Dog(BaseModel):
    pet_type: Literal["dog"]
    barks: float


class Lizard(BaseModel):
    pet_type: Literal["reptile", "lizard"]
    scales: bool


Pet = TypeAliasType(
    "Pet",
    Annotated[Cat | Dog | Lizard, Field(discriminator="pet_type")],
)


bare_app = FastAPI(title="Bare Pet Example")


@bare_app.post("/pets")
def create_bare_pet(pet: Pet):
    return pet


@bare_app.get("/debug-openapi")
def debug_bare_openapi():
    schema = bare_app.openapi()
    request_schema = schema["paths"]["/pets"]["post"]["requestBody"]["content"][
        "application/json"
    ]["schema"]

    return {
        "request_schema": request_schema,
        "components": list(schema.get("components", {}).get("schemas", {}).keys()),
    }


body_app = FastAPI(title="Body Pet Example")


@body_app.post("/pets")
def create_body_pet(pet: Annotated[Pet, Body()]):
    return pet


@body_app.get("/debug-openapi")
def debug_body_openapi():
    schema = body_app.openapi()
    request_schema = schema["paths"]["/pets"]["post"]["requestBody"]["content"][
        "application/json"
    ]["schema"]

    return {
        "request_schema": request_schema,
        "components": list(schema.get("components", {}).get("schemas", {}).keys()),
    }


app = FastAPI(title="Compare TypeAliasType OpenAPI Behavior")
app.mount("/bare-case", bare_app)
app.mount("/body-case", body_app)
```


### Description

I wanted to check whether this OpenAPI behavior is expected before opening an issue or PR.

I am using a named Pydantic `TypeAliasType` for a top-level discriminated union request body. Runtime validation works correctly in both cases, but the generated OpenAPI differs depending on whether the parameter is written as a bare annotation or explicitly wrapped with `Body()`.

This came up while looking at this Pydantic issue: https://github.com/pydantic/pydantic/issues/13236

My understanding from that discussion is that Pydantic validation/schema generation is working, and that the remaining discrepancy may be in FastAPI’s OpenAPI/request-body handling.

I also searched for related FastAPI issues/discussions and found #10719, #12149, #13635, and #13920, which seem related to FastAPI’s handling of PEP 695 / `TypeAliasType` aliases with `Annotated` metadata. Those appear to be addressed by #13920. I am using FastAPI 0.136.1, so this should include those fixes, but this specific OpenAPI component behavior still reproduces.

Run the example with:

```bash
uvicorn main:app --reload
```

Then open:

```text
http://127.0.0.1:8000/bare-case/debug-openapi
http://127.0.0.1:8000/body-case/debug-openapi
http://127.0.0.1:8000/bare-case/docs
http://127.0.0.1:8000/body-case/docs
```

With the bare annotation:

```python
@bare_app.post("/pets")
def create_bare_pet(pet: Pet):
    return pet
```

FastAPI emits the request body schema inline:

```json
{
  "oneOf": [
    {"$ref": "#/components/schemas/Cat"},
    {"$ref": "#/components/schemas/Dog"},
    {"$ref": "#/components/schemas/Lizard"}
  ],
  "title": "Pet",
  "discriminator": {
    "propertyName": "pet_type",
    "mapping": {
      "cat": "#/components/schemas/Cat",
      "dog": "#/components/schemas/Dog",
      "reptile": "#/components/schemas/Lizard",
      "lizard": "#/components/schemas/Lizard"
    }
  }
}
```

The generated components do not include `Pet`:

```text
["Cat", "Dog", "HTTPValidationError", "Lizard", "ValidationError"]
```

With the explicit `Body()` annotation:

```python
@body_app.post("/pets")
def create_body_pet(pet: Annotated[Pet, Body()]):
    return pet
```

FastAPI emits:

```json
{"$ref": "#/components/schemas/Pet"}
```

and the generated components include `Pet`:

```text
["Cat", "Dog", "HTTPValidationError", "Lizard", "Pet", "ValidationError"]
```

I also confirmed visually in Swagger UI that `/bare-case/docs` does not show a reusable `Pet` schema under Schemas, while `/body-case/docs` does.

Both route parameters represent the same logical request body type:

```python
Pet = TypeAliasType(
    "Pet",
    Annotated[Cat | Dog | Lizard, Field(discriminator="pet_type")],
)
```

The bare annotation validates correctly, and the inline schema has the correct `title`, `oneOf`, and discriminator metadata. However, only `Annotated[Pet, Body()]` preserves the named alias as a reusable OpenAPI component.

My question: Is this expected behavior?

Would it make sense for FastAPI to preserve the named schema component for a bare named Pydantic `TypeAliasType` request body, matching the `Annotated[Pet, Body()]` behavior?

If this is considered valid behavior to align, I would be happy to contribute a focused regression test or small PR.
