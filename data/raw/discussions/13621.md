### Description

Hello,

I'm working on a project using fastapi and running into an issue with the intermingling of non-async fastapi routes, and async code.

In particular:
* My project uses non-async fastapi routes / endpoints (I cannot immediately migrate to `async` ones)
* As part of handling some API requests, I need to use a client library which under the hood makes use of asyncio e.g. via `get_event_loop().run_until_complete(some_func)`

Naively doing this results in a crash due to no active event loop in the thread handling the fastapi endpoint:
```
...
    get_event_loop().run_until_complete(some_coroutine)
    ~~~~~~~~~~~~~~^^
  File "/Users/myuser/.local/share/uv/python/cpython-3.13.2-macos-aarch64-none/lib/python3.13/asyncio/events.py", line 716, in get_event_loop
    raise RuntimeError('There is no current event loop in thread %r.'
                       % threading.current_thread().name)
RuntimeError: There is no current event loop in thread 'AnyIO worker thread'.

```
See also my example code for a minimal reproducible example of the issue.

My question is twofold:

1. What is the best way to ensure there is an active event loop without changing every single route? In particular I tried to add a `ensure_event_loop_initialized` method which makes sure an event loop is indeed initialized at the middleware layer, but it doesnt solve the issue, apparently because the middle ware may run on a different thread than the actual endpoint handler. Similarly, I am able to run it via a depends clause on individual routers , e.g `router = APIRouter(dependencies=[Depends(ensure_event_loop_started)])`. This seems to work but I read somewhere on the github issues that this is also not guaranteed to be run in same thread as request handling?
2. How bad is it to have an event loop as part of sync. fastapi request handling functions to begin with? I assume its not ideal but for cases like this where I need to make legacy code work with fastapi is this more or less supported use case?


Thank you.

## Accepted answer by YuriiMotov (MEMBER)

Event loop is running in the main thread, but your endpoint function is executed in different thread. That's why you are getting "There is no current event loop in thread".

You need to get event loop in the main thread and save it somewhere (e.g. in app state):

```
from asyncio import AbstractEventLoop, sleep
import asyncio
from contextlib import asynccontextmanager
from typing import Annotated, cast

from fastapi import Depends, FastAPI, Request


@asynccontextmanager
async def lifespan(app: FastAPI):
    yield {"event_loop": asyncio.get_event_loop()}


app = FastAPI(lifespan=lifespan)


async def some_coroutine():
    await sleep(2)
    print("Hello, from async function!")


async def get_event_loop(request: Request) -> AbstractEventLoop:
    return cast(AbstractEventLoop, request.state.event_loop)


@app.get("/")
def my_non_async_endpoint(
    event_loop: Annotated[AbstractEventLoop, Depends(get_event_loop)],
):
    t = asyncio.run_coroutine_threadsafe(some_coroutine(), loop=event_loop)
    t.result(timeout=3.0)
    return {"Hello": "world"}
```
