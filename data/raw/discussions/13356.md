## Accepted answer by jgould22 (NONE)

> it has sync call what i have seen is that sometime worker gets timeout befor

It sounds like your worker might be blocking the event loop and causing gunicorn to not be able to check on it 

You need to spawn any long running sync work to a thread pool so it doesnt block the event loop. 

~~Unfortunately I cant seem to find any docs on Starlettes [run_in_thread_pool()](https://github.com/encode/starlette/blob/master/starlette/concurrency.py#L35) but you can use this on your sync code so your worker doesnt block~~

Use [`anyio.to_thread.run_sync` ](https://anyio.readthedocs.io/en/stable/threads.html)to run your blocking code without impacting the event loop
