### Description

Before PR #14459:
The public attribute `dependant.security_requirements` existed and worked normally.

After PR #14459:
 Accessing `dependant.security_requirements` raises AttributeError.
 Error message: 'Dependant' object has no attribute 'security_requirements'

Root cause:
The public field `security_requirements` was directly removed from the Dependant class in dataclass definition, without any backward compatibility, deprecation warning, or fallback property.

This is a regression bug and API breaking change.

### Additional Context

The PR fixed OAuth2 scope handling in OpenAPI but accidentally broke backward compatibility by completely removing the public `security_requirements` attribute from the Dependant dataclass.

The correct fix should be:
 Add a @property fallback for backward compatibility
 Add a DeprecationWarning
 Keep external code from breaking

Currently, any external tool, plugin, or test that accesses dependant.security_requirements will crash with AttributeError.

## Accepted answer by YuriiMotov (MEMBER)

`Dependant` is not a part of public API. It's not documented in docs.

For now FastAPI doesn't have public API for integrations with other libs.
We have this in our plan, but for now you should pin FastAPI version and test before upgrading to newer version to prevent breaking your integration
