### Example Code

```python
import time
from fastapi import FastAPI

app = FastAPI()
prev_args = []

async def slow(waiting: float) -> str:
    time.sleep(waiting)
    prev_args.append(waiting)
    return "ok"


@app.post("/deal")
async def deal(waiting: float):
    print(waiting)
    await slow(waiting)
```


### Description

I need the `deal` route to process `slow` somewhere (a subprocess, maybe) and return ASAP. The client should be able to call `deal` again and there should be two concurrent executions.

If I use the example code, the `slow` call is awaited and blocks.
If I instead do not await it, I get a "RuntimeWarning: coroutine slow was never awaited"

At this point I´m using a `subprocess.Popen` inside `slow` instead of the `time.sleep`, as what I need to do can be done in that way.
And I have `deal` and `slow` to be regular `def` instead of `async` ones.
But I´d rather replace `subprocess.Popen` with a direct call to the 3rd party lib that I need to use.

So, my question is whether I can resort to something more standard.

## Accepted answer by luzzodev (CONTRIBUTOR)

Hello @matiasg,

what are your asking can be done in several ways:
If your 3dparty call is pure async and not cpu intensive, you can use BackgroundTask from Fastapi.
If is cpu bound you can work with multiprocessing and queues. 
If you need something more structured and ready to go you can check Celery or other libs that do the same.
