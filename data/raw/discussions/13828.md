### Example Code

```python
from fastapi import FastAPI
from pydantic import BaseModel
from fastapi import HTTPException, Depends


router = FastAPI()


class UpdateUser(BaseModel):
    rank: int


def validate_body(args: UpdateUser):
    if args.rank > 100:
        raise HTTPException(status_code=400, detail="Invalid rank")

    return args


@router.patch("/user/{user_id}", operation="user.update_user")
def update_user(args: UpdateUser, args_from_dependency: UpdateUser = Depends(validate_body)):
    assert args is args_from_dependency
```


### Description

When endpoint `PATCH` `/user/{user_id}` from example above is requested - FastAPI creates two `UpdateUser` instances(probably, runs validation twice for each parameter).

Expected behavior is that the FastAPI don't revalidates body, if it is already validated

## Accepted answer by YuriiMotov (MEMBER)

I agree that we shouldn't validate request parameters twice.

The main reason is that it gives us duplicated error messages in case of validation error.
Several related discussions:
* https://github.com/fastapi/fastapi/discussions/8669
* https://github.com/fastapi/fastapi/discussions/8659
* https://github.com/fastapi/fastapi/discussions/9005

As I see it, we should validate parameters once and then use its deep-copy for each instance.

If it's important in your use-case that only one instance is used, you can use the chain of dependencies (create dependency that returns parameter and use it in other dependencies) to achieve this
