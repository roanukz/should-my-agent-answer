### Example Code

```python
import uvicorn
from fastapi import Depends, FastAPI
from pydantic import BaseModel, ConfigDict

app = FastAPI()

class TestParams(BaseModel):
    model_config = ConfigDict(defer_build=True)
    x: int = 1

@app.get("/")
async def index_route(
    params: TestParams = Depends()
) -> None:
    return

if __name__ == "__main__":
    uvicorn.run(app, host="0.0.0.0", port=8000)
```

### Description

We're attempting to use Pydantic's defer_build functionality to improve developer env boot times by delaying pydantic model building to when we actually need to use it. It appears that fastapi gets confused by the defer_build param (see repro). The error returned is:
`{"detail":[{"type":"missing","loc":["query","data"],"msg":"Field required","input":null}]}`

This does not reproduce when the model_config is commented out. I'm surprised no one else has reported this so far based on searching, so filing a bug here. Not super clear if it's a pydantic or fastapi issue here - it feels like given what pydantic claims to happen with defer_build=True, fastapi should make sure to call model_build() on any pydantic model classes being used in route construction calls?

## Accepted answer by luzzodev (CONTRIBUTOR)

Hello @davidhao3300,
the official supported way to use Model in query is the following, and actually support even your use-case.

``` python
import uvicorn
from typing import Annotated
from fastapi import FastAPI, Query
from pydantic import BaseModel, ConfigDict

app = FastAPI()

class TestParams(BaseModel):
    model_config = ConfigDict(defer_build=True)
    x: int = 1

@app.get("/")
async def index_route(
    params: Annotated[TestParams, Query()]
) -> None:
    return

if __name__ == "__main__":
    uvicorn.run(app, host="0.0.0.0", port=8000)
```

If you use `Depends` like you did, FastApi will try to inspect the signature of a model that has not been created yet.
