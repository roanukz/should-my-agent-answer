### Example Code

```python
@router.get(
    "/sensor/{sensor_id}"
)  # , response_model=List[MeasurementTimeBucketResponse]
async def get_sensor_measurements(
    sensor_id: int,
    start_time: Optional[datetime] = datetime.utcnow() - timedelta(days=1),
    end_time: Optional[datetime] = datetime.utcnow(),
    aggregation_function: str = "avg",
    interval: str = "1 hour",
    measurement_db: MeasurementDB = Depends(get_timescale_db),
    current_user: dict = Depends(get_current_active_user),
):
    try:
        ts = time.time()
        measurements = await measurement_db.get_measurements(
            sensor_id=sensor_id,
            start_time=start_time,
            end_time=end_time,
            aggregation_function=aggregation_function,
            aggregation_interval=interval,
        )
        print(f"DB fetch time: {time.time() - ts}")

        ts = time.time()
        response = [
            MeasurementTimeBucketResponse(**measurement) for measurement in measurements
        ]
        print(f"Pydantic time: {time.time() - ts}")

        ts = time.time()
        json_response = orjson.dumps(
            jsonable_encoder(response), option=orjson.OPT_APPEND_NEWLINE
        )
        print(f"Response time: {time.time() - ts}")

        return Response(content=json_response, media_type="application/json")
    except Exception as e:
        raise HTTPException(
            status_code=status.HTTP_500_INTERNAL_SERVER_ERROR, detail=str(e)
        )
```

### Description

When I query this endpoint I get these timings:

DB fetch time: 0.15195035934448242
Pydantic time: 0.17268824577331543
Response time: 0.5988411903381348

When I try the endpoint in the `/docs`, it simply is too much for the browser to render and get "Maximum call stack size exceeded".

However, in my frontend I see that the whole request takes 2 seconds and 1.8 of it is "waiting for server response".
It is actually faster if I just pass the pydantic objects and let fastapi do the serialization, then the whole request takes 1.6 seconds.

How can I speed this up?

## Accepted answer by sachinh35 (NONE)

Hi, I'm not sure if you're still facing this issue or not but just wanted to follow up on this. Sorry for the long delay. From this [blog](https://blog.cloudflare.com/a-question-of-timing/):
> time_starttransfer is just before cURL reads the first byte from the network (it hasn't actually read it yet). This includes the round trip over the network, .....

So your backend server is taking close to 0.47s to calculate the response **before** sending it back completely over the network. I'm not sure how much further you can speed this up without vertically scaling your compute but that's all I can help you with for now without taking a good look at the code. Perhaps there are other ways you can speed up your response calculation time but that's beyond the scope of FastAPI's support. 

To conclude, from the POV of FastApi, I think the only step you can take to speed things up is to dump the JSON yourself instead of relying on FastAPI to do it. Good luck with your project!
