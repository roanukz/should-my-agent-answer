### Example Code

```python
from typing import Annotated
from fastapi import FastAPI, Form
from fastapi.testclient import TestClient
from pydantic import BaseModel

app = FastAPI()

class UploadForm(BaseModel):
    name: str
    file: bytes

@app.post("/upload/")
async def upload(data: Annotated[UploadForm, Form()]):
    return {"name": data.name, "size": len(data.file)}

client = TestClient(app)
response = client.post(
    "/upload/",
    files={"file": ("test.txt", b"hello world", "text/plain")},
    data={"name": "test"},
)
print(response.status_code)
print(response.json())
```

### Description

```
I am using a Pydantic BaseModel with Form() to group form fields together. 
When one of the fields is annotated as `bytes`, FastAPI does not call 
`read()` on the uploaded file and returns a 422 error instead.

What I expect:
- Status 200, FastAPI automatically reads the UploadFile into bytes,
  exactly as it does when `bytes` is a standalone File() parameter.

What actually happens:
- Status 422, `bytes_type` validation error. The raw UploadFile object 
  is passed directly to Pydantic without being read first.

This works fine (standalone):

    @app.post("/works/")
    async def works(file: bytes = File()):
        return {"size": len(file)}  # ✅ 200

This breaks (inside a Pydantic model):

    class UploadForm(BaseModel):
        file: bytes

    @app.post("/breaks/")
    async def breaks(data: Annotated[UploadForm, Form()]):
        return {"size": len(data.file)}  # ❌ 422

Affected annotations inside a Pydantic Form model:

| Annotation          | Works? |
|---------------------|--------|
| file: UploadFile    |  Yes |
| file: UploadFile|None | Yes |
| file: list[UploadFile] |  Yes |
| file: bytes         |  No  |
| file: bytes | None  |  No  |
| file: list[bytes]   |  No  |

I looked into the source code. The issue is in `_extract_form_body()` 
in `fastapi/dependencies/utils.py`. The guard:

    isinstance(field_info, params.File)

is always False for fields extracted from a Pydantic model because 
those fields have plain Pydantic FieldInfo, not params.File.
So `read()` is never called on the UploadFile.

I would be happy to work on a fix if this is confirmed.
```

## Accepted answer by YuriiMotov (MEMBER)

Declaring file upload fields using Pydantic model is not officially supported ([see comment to closed PR](https://github.com/fastapi/fastapi/pull/14343#issuecomment-3600534954)).

To make your example work, you need to add `File()` annotation to `file` field:

```py
class UploadForm(BaseModel):
    name: str
    file: Annotated[bytes, File()]
```

And specify `media_type="application/x-www-form-urlencoded"` as follows to make schema correct:

```py
@app.post("/upload/")
async def upload(data: Annotated[UploadForm, Form(media_type="application/x-www-form-urlencoded")]):
    return {"name": data.name, "size": len(data.file)}
```

One more time: this is not officially supported. You can use it on your own risk)
