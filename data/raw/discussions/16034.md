### Example Code

```python
# pip install "fastapi==0.139.2" freezegun httpx

from datetime import date
from typing import Annotated, Optional
from fastapi import APIRouter, FastAPI, Query
from fastapi.testclient import TestClient
from freezegun import freeze_time

router = APIRouter()

@router.get("/m")
def handler(from_date: Annotated[Optional[date], Query()] = None):
    return {"from_date": str(from_date)}

# App built ONCE, outside any freeze (like importing your app at startup).
app = FastAPI()
app.include_router(router, prefix="/api")
client = TestClient(app, raise_server_exceptions=True)

# App's FIRST request, made while the clock is frozen.
with freeze_time("2024-05-13"):
    print(client.get("/api/m").status_code)
```


### Description

Since 0.137.0, if I understand correctly, a route's parameter fields are built lazily at first request/match time (the `router.routes` tree / `effective_candidates` change) instead of at registration time. If that first build happens while `freezegun`'s `@freeze_time` is active, pydantic cannot generate a core schema for `datetime.date` and the request 500s:

```
fastapi.exceptions.FastAPIError: Invalid args for response field! ... typing.Annotated[typing.Optional[datetime.date], Query(PydanticUndefined)] ...
```

Caused by:

```
pydantic.errors.PydanticSchemaGenerationError: Unable to generate pydantic-core schema for <class 'datetime.date'>
```

Last good: 0.136.x. First bad: 0.137.0. Still present: 0.139.2.

Output:
- 0.136.x → 200
- 0.137.0 / 0.139.2 → 500 (raises the error)

## Accepted answer by YuriiMotov (MEMBER)

I think this is an incompatibility issue between Pydantic and FreezGun and it should be reported\addressed there.

I found 2 related discussions (there are more):
* https://github.com/spulec/freezegun/issues/551

In the comments people recommend switching to time-machine. Have you considered this?
