### Description

I have an application which make heavy use of dependencies. I have deeply nested dependencies, since the application has grown. It keeps the code super clean and modular, which is a plus. 

I noticed recently that I wasn't able to hit the load performance I needed. I was tinkering with the code trying to figurate out where the bottleneck could be. To my surprise I noticed that the dependencies was the root cause of it. If I completely removed them from my router definition, I'd achieve very high RPS. As soon as I add one, my RPS would drop. With all of them added, I'd get back to where I started. In essence, I go from 1800 -> 200 RPS. These tests where done in my machine, locally, running the the app with `fastapi run dev`. 

I created an MVP to observe this decay. I added a simple `main.py` with three routes. One without any dependency, a single dependency and a nested dependency. I run the load test on each one of these endpoints individually. I observed very similar behavior. 

![image](https://github.com/user-attachments/assets/2fcd7c63-a47e-40c0-b4d1-31868b91619b)

From left to right, without dependency, single dependency and nested dependency run, respectively. We can clearly see the drop in RPS we can produce. I've tried to keep the tests as objective as possible, by running them back to back in the exact same conditions, but feel free to suggested a better testing method. 

I guess my question here is if this is completely expected, since in essence we are calling functions to resolve values at runtime during the request flow? I would expect some degradation of performance, but 10-20% seems extreme. 

If the goal of dependencies is not to instantiate clients and keep code modular, as I am doing in my actual app, please educate me :) 

Thank you,

## Accepted answer by YuriiMotov (MEMBER)

I just wanted to say that you should compare endpoints that do equal job. It's useless to compare the performance of endpoint that doesn't accept any parameters with the endpoint that accepts and validates several parameters.

The following code compares 3 endpoints with equal functionality. And it shows that the difference (average) is very small:

```python
from functools import lru_cache
from typing import Annotated, Any

import pydantic_settings
from fastapi import Depends, FastAPI, Request 

app = FastAPI()


class EnvSettings(pydantic_settings.BaseSettings):
    env: str = "LOCAL"


@lru_cache
def _get_env_settings() -> EnvSettings:
    return EnvSettings()


async def get_env_settings() -> EnvSettings:
    return _get_env_settings()


async def common_parameters(
    env: Annotated[EnvSettings, Depends(get_env_settings)],
    q: str | None = None,
    skip: int = 0,
    limit: int = 100,
):
    return {"q": q, "skip": skip, "limit": limit, "env": env.env}


@app.get("/users-with-nested-dependency/")
async def read_users_with_nested_dependency(
    commons: Annotated[dict[str, Any], Depends(common_parameters)],
):
    return {
        "env": commons["env"],
        "q": commons["q"],
        "skip": commons["skip"],
        "limit": commons["limit"],
    }


@app.get("/users-with-minimal-dependency/")
async def read_users_with_dependency(
    q: str | None = None, skip: int = 0, limit: int = 100
):
    env = _get_env_settings()
    return {
        "env": env,
        "q": q,
        "skip": skip,
        "limit": limit,
    }


@app.get("/users-without-dependencies/")
async def read_users_without_dependency(request: Request):
    q = request.query_params.get("q")
    skip = int(request.query_params.get("skip", 0))
    limit = int(request.query_params.get("limit", 100))
    env = _get_env_settings()
    return {
        "env": env,
        "q": q,
        "skip": skip,
        "limit": limit,
    }

```
