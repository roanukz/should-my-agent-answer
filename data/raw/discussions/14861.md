### Description

I am using FastAPI in a server that is set up with Unix domain sockets. In a logon API call, I want to get the real UID of the user of the client process in order to generate a JWT from it.

This is possible if one has the underlying socket object. However, FastAPI does not seem to provide a means to get hold of the socket object.

I found only complex approaches for that, e.g. to run a socket based server for the logon API call, or to wrapper the socket/app for FastAPI.

I think that FastAPI should provide a convenient way to access the underlying socket object.

## Accepted answer by YuriiMotov (MEMBER)

FastAPI's `HTTPConnection` (base class for `Request` and `WebSocket`) is just a re-export of Starlette's `HTTPConnection`: https://github.com/fastapi/fastapi/blob/cd31576d5704b6aef1bdadc43770238cd88aad2b/fastapi/requests.py#L1

So, I think you should ask this in Starlette repository: https://github.com/Kludex/starlette/discussions
