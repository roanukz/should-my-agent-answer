### Example Code

```python
from fastapi import FastAPI
from fastapi.responses import HTMLResponse

class CustomHTML:
    def __html__(self) -> str:
        return "<h1>Hello</h1>"

app = FastAPI()

@app.get("/")
def root():
    return HTMLResponse(CustomHTML())
```


### Description

Gets AttributeError because HTMLResponse only takes str and won't try to `__html__` to convert it into `str` first.

Expected: return the str given by `content.__html__()`.

Implementation:

```python
if hasattr(content, "__html__"):
     content = content.__html__()
```

### Additional Context

The `__html__` method is a widely used method for signaling safe HTML output (that needs no escaping, and that isn't repr for which there is `_repr_html_`). This is used by templating and web frameworks (Django, Jinja2, Sanic).

## Accepted answer by yakubka (NONE)

HTMLResponse is defined in Starlette, not FastAPI, so the `__html__` support would need to live there. FastAPI's `HTMLResponse` is just a re-export of `starlette.responses.HTMLResponse`.

The current implementation passes `content` directly to the `Response` body, which calls `.encode()` and expects a string or bytes. There is no protocol hook for arbitrary objects.

For now the explicit workaround is to call `__html__` yourself at the call site:

```python
@app.get("/")
def root():
    return HTMLResponse(CustomHTML().__html__())
```

If you want to avoid spelling that out on every route, a thin subclass works:

```python
from fastapi.responses import HTMLResponse

class SmartHTMLResponse(HTMLResponse):
    def __init__(self, content=None, **kwargs):
        if content is not None and not isinstance(content, (str, bytes)) and hasattr(content, "__html__"):
            content = content.__html__()
        super().__init__(content=content, **kwargs)
```

Use `SmartHTMLResponse` as your `response_class` and it transparently handles objects that implement `__html__`.

For upstreaming the feature, I would open the discussion or PR in the Starlette repo rather than FastAPI. The `__html__` protocol is well established in the Python web ecosystem (Jinja2, MarkupSafe, Django's `mark_safe`) so it has a reasonable case for first-class support, but the change belongs in Starlette's `Response.__init__` where the content encoding actually happens.
