# Multiple arguments annotated with Query()

Discussion #13708 · 2025-05-12T12:49:41Z · https://github.com/fastapi/fastapi/discussions/13708

## Question

### Example Code

```python
from typing import Annotated

from fastapi import FastAPI, Query
from pydantic import BaseModel, Field

app = FastAPI()


class FilterParams(BaseModel):
    limit: int = Field(100, gt=0, le=100)
    offset: int = Field(0, ge=0)
    tags: list[str] = []


@app.get("/items/")
async def read_items(
        filter_query: Annotated[FilterParams, Query()],
        tenant: Annotated[str, Query()] = 'main'
):
    return filter_query, tenant
```


### Description

According to this docs page [query-param-models](https://fastapi.tiangolo.com/tutorial/query-param-models/?h=query#check-the-docs):
"If you have a group of query parameters that are related, you can create a Pydantic model to declare them."

This suggests that one can pick a subset of query parameters and group them in a Pydantic model, whille leaving some explicitly specified as endpoint args (see Example Code).
This, however, leads to inconsistent swagger docs, which produce a form (and also a `curl` command) that is incorrect. In fact, there seems to be no correct way to send a request that gets correctly verified in this case (always returns 422 Unprocessable Entity).

Potential solutions: 
- either handle the case (include both attributes from the pydantic object and the explicit ones)
- OR mark in the documentation as Bad Practice, possibly handle errors earlier in case of multiple query arguments, if at least one is a pydantic model
