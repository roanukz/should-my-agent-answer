### Example Code

```python
class Orchestrator:
    def __init__(
        self,
        controller_1: Annotated[Controller1, Depends(Controller1)],
        controller_2: Annotated[Controller2, Depends(Controller2)],
        controller_3: Annotated[Controller3, Depends(Controller3)],
        controller_4: Annotated[Controller4, Depends(Controller4)],
        controller_5: Annotated[Controller5, Depends(Controller5)],
    ):
        self._controller_1 = controller_1
        self._controller_2 = controller_2
        self._controller_3 = controller_3
        self._controller_4 = controller_4
        self._controller_5 = controller_5

    
    async def process_payload(self, payload) -> None:
        common_pre_logic(payload)
        
        match payload.type:
            case "type_1":
                await self._controller_1.handle(payload)
            case "type_2":
                await self._controller_2.handle(payload)
            case "type_3":
                await self._controller_3.handle(payload)
            case "type_4":
                await self._controller_4.handle(payload)
            case "type_5":
                await self._controller_5.handle(payload)
        
            case _:
                raise ValueError(f"Unknown payload type: {payload.type}")

        common_post_logic(payload)
```


### Description

I'd like the ability for the dependency injection system to lazily initialize deps, similar to how Dagger does it with a `@lazy` annotation or similar.

ie. Declare many dependencies in a class/endpoint, and only initialize the ones that are used.

The example use-case is a top-level Orchestrator which initializes the right Controller depending on the payload. All requests for one part of the app are processed via the Orchestrator, which is injected into the API endpoint.

We are currently forced to choose between two options:
1. Automatically instantiate many controllers which aren't used (could be 20+)
2. Create a dedicated method to initialize the right controller for the given payload. But the controller has to be manually created using the constructor or a factory method like `controller = Controller1()`, which prevents us from their dependencies using DI.

Lazy initialization solves this.

(Also, in my example, I do not want the `Controller` classes to depend on the `Orchestrator` - that inverts the hierarchy of responsibility. Especially if the orchestrator might need to use 2 controllers, etc.)

## Accepted answer by YuriiMotov (MEMBER)

The problem with openapi I mentioned before is:

Imagine your ControllerXX dependencies have required Query parameters

```
class Controller1:
    def __init__(self, limit: int):
        ...

class Controller2:
    def __init__(self, count: int):
        ...
```

In your case there probably no need to add request parameters, but in general dependencies allow this and we will need to handle this.

Now you want to choose one of these controllers depending on payload.
Currently both, `limit` and `count` will be required. But you probably expect only one of them to be required depending on the payload. But it's currently impossible to declare such schema (with conditional Query parameters) in openapi.
