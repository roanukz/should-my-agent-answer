### Example Code

```python
from fastapi import FastAPI, WebSocket, WebSocketDisconnect
from fastapi.testclient import TestClient

import asyncio

app = FastAPI()


@app.websocket("/ws")
async def websocket_endpoint(websocket: WebSocket):
    await websocket.accept()
    try:
        while True:
            text = await websocket.receive_text()
            if text == "action":
                await websocket.send_text("done")
    except WebSocketDisconnect:
        return await websocket.close()


async def test_websocket_timeout():
    client = TestClient(app)
    with client.websocket_connect("/ws") as ws:
        ws.send_text("action")
        assert ws.receive_text() == "done"
        ws.send_text("not-action")
        # freezes without timing out
        ws.receive_text()
        # still freezes without timing out
        assert await asyncio.wait_for(ws.receive_text(), 1.0) != "done"
```


### Description

I'm trying to implement a timeout for the websocket receive_{text, bytes, json} functions, but it doesn't work no matter what. Even with asyncio.wait_for it still freezes on ws.receive_text and waits for an answer. I'm trying to use this in testing so I can test if other connections are not receiving the secret information. Any help is greatly appreciated.

## Accepted answer by luzzodev (CONTRIBUTOR)

Hello @zmn-hamid,

TestClient is from Starlette, so any improvements or suggestions should probably be addressed there.

Your test example is freezing because `receive_text()` is synchronous and will not be interrupted by `wait_for`.

Something like the following should work in your case:
``` python

@pytest.mark.asyncio
async def test_websocket_timeout():
    with client.websocket_connect("/ws") as ws:
        ws.send_text("action")
        assert ws.receive_text() == "done"
        ws.send_text("not-action")
        with pytest.raises(asyncio.TimeoutError):
            await asyncio.wait_for(run_in_threadpool(ws.receive_text), 1.0)
```

In general, I think it would be better to use an external WebSocket library for testing. I also found a related discussion on Starlette that might be relevant (https://github.com/encode/starlette/discussions/2195).
