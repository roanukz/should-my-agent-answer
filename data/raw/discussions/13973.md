### Description

The documentation says that whether you use an async or sync dependency, "FastAPI will know what to do." If I want to write a custom dependency and provide it through a Python package, should I include only the async version, or both async and sync versions?

What's the point of providing a sync version if users could just use the async one anyway? Are there valid use cases where a sync version is preferable or even required?

I think this could be clarified a bit more in the documentation.

## Accepted answer by YuriiMotov (MEMBER)

`async` dependency will be solved in event loop. This is fast, but the code of your dependency function shouldn't block event loop.

non-`async` dependency will be solved in thread pool. This brings some overheads (thread pool size is limited and your function execution may be delayed).

If your dependency doesn't contain any code that may block the event loop (e.g. heavy computations or blocking (non-`async`) IO-operations) - make it `async`.
You will only need non-`async` version if your dependency function contains code that may block event loop.
