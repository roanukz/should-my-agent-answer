### Description

Hello
I have an app with a lot of unit tests. When I call the POST /folders endpoint, with an unexisting email, an UserWithEmailNotFound exception is thrown by create_or_update_folder

create_folder function is catching it, and then returns a JSONResponse with a comprehensive message in detail key.

With 0.123.10 version of FastAPI, everything is working well
When I update to 0.124.0, a lot of newline characters are inserted in my error message:

```
>       self.assertEqual(
            data["detail"], "Assigned user with email unknown@email.com not found."
        )
E       AssertionError: '53 validation errors:\n  A\n  s\n  s\n  i[241 chars]n  .' != 'Assigned user with email unknown@email.com not found.'
E       + Assigned user with email unknown@email.com not found.
E       - 53 validation errors:
E       -   A
E       -   s
E       -   s
E       -   i
E       -   g

E       -   e
E       -   d
```

I read the changelog of the 0.124.0 version, and I wonder if it can be a regression: the commit https://github.com/fastapi/fastapi/pull/14306 helps debugging by adding stacktrace in error messages

I will try to analyze more, to see if I understand the root cause

## Accepted answer by YuriiMotov (MEMBER)

Actually, I think I found the issue.
`ValidationException` has one positional argument `errors: Sequence[Any]` and you are passing a single string to it. This string is also a sequence of strings (sequence of characters).
Try raising the error passing a list with that single string:

```diff
def create_or_update_folder(...):
    user = get_user_by_email(db, assigned_user_email)
    if not user:
        raise UserWithEmailNotFound(
-            f"Assigned user with email {assigned_user_email} not found."
+            [f"Assigned user with email {assigned_user_email} not found."]
        )
```

Or, modify `UserWithEmailNotFound` to accept `error: str` and pass it to parent constructor as `errors=[error]`
