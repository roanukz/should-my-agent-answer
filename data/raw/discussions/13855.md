### Description

I’d like to propose extracting the fastapi.status module into its own standalone package (e.g. fastapi-status) that can be installed and imported separately from FastAPI.

Motivation:
- Many projects outside FastAPI want to use HTTP status codes like `status.HTTP_200_OK `for readability and consistency.
- Python’s standard library http.HTTPStatus is less ergonomic, using names like HTTPStatus.OK instead of `HTTP_200_OK`.
- Keeping status in FastAPI means that unrelated projects must install all of FastAPI just to access these constants.

## Accepted answer by sachinh35 (NONE)

The Fast API `status` module is actually from Starlette. Ref: https://github.com/encode/starlette/blob/fa5355442753f794965ae1af0f87f9fec1b9a3de/starlette/status.py#L15

I can see how Starlette's status codes can be more intuitive to use as they include the error code and the error reason in the variable name. However, IMO it's just a single file so not worth creating a standalone module just for it. 

Feel free to import that file and re-use it directly in your project!
