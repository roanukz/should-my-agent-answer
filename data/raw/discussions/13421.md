### Example Code

```python
from fastapi import FastAPI

API = FastAPI()

...

# Create a sub-application
PUBLIC_API = FastAPI()

...

API.mount("/public", PUBLIC_API)
```


### Description

Issue occurs when using a root path along with an application mount. In the example above the sub application is mounted in "/public". 

When running the fastapi server with a root path i.e. root_path="/api/app-name" the docs aren't retrievable for the mounted application in the namespace "/api/app-name/public/docs" (traefik is required to run locally). The docs below are referenced:

 https://fastapi.tiangolo.com/advanced/behind-a-proxy/#checking-the-current-root_path
https://fastapi.tiangolo.com/advanced/behind-a-proxy/#about-proxies-with-a-stripped-path-prefix

Running the server on port 8000 and heading to port 8000:

GET:
 http://127.0.0.1:8000/api/app-name/public/docs 
(200)

GET:
 http://127.0.0.1:8000/api/app-name/docs 

When running traefik and fastapi version fastapi==109.0:
./traefik --configFile=traefik.toml

GET:
http://127.0.0.1:9999/api/app-name/docs
(200)

GET:
http://127.0.0.1:9999/api/app-name/public/docs
(404)

Would expect a status of 200 and the docs to be returned.

However running fastapi version fastapi==108.0, the docsite is returned as expected:
GET:
http://127.0.0.1:9999/api/app-name/public/docs
(200)

Is there a work around or change required for fastapi versions >=109.0?

Many thanks!
Alex

## Accepted answer by luzzodev (CONTRIBUTOR)

Hello @poppyi-domain, from v0.109.0 the behaviour of `root_path` has changed a bit. 
You can follow https://github.com/fastapi/fastapi/issues/10978.

If you want to mantain the old behaviour, you can configure the root_path on uvicorn or fastapi command.

-  `fastapi run main.py --app "API" --root-path "/api/v1"`
- `uvicorn main:API --root-path "/api/v1"`
- `uvicorn.run(API, root_path="/api/v1")`

If you set the root-path on the Fastapi instance, it will require the unstripped path from traefik.
