### Example Code

```python
from fastapi import FastAPI, Query
from pydantic import BaseModel
from typing import Annotated
from pydantic import MinLen

app = FastAPI()

class QueryModel(BaseModel):
    descriptions: Annotated[list[str], MinLen(1)] | None = None

@app.get("/test")
def test(query: QueryModel = Query()):
    return {"descriptions": query.descriptions}
```


### Description

Using a Pydantic model with `Annotated[list[str], MinLen(1)]` as a query parameter via `Depends()` causes a 422 error — even when multiple query parameters are passed (`?descriptions=a&descriptions=b`). This looks like a regression in the FastAPI + Pydantic v2 integration.

```
GET /test?descriptions=a&descriptions=b
```

should result in 

```
{
  "descriptions": ["a", "b"]
}
```

but results in

```
422 Unprocessable Entity
{
  "detail": [
    {
      "type": "list_type",
      "loc": ["query", "descriptions"],
      "msg": "Input should be a valid list",
      "input": "a"
    }
  ]
}
```

I know that this behavior works correctly if we use `Query(..., min_length=1)` directly in the route function or in model class but I think syntax with `Annotated` should be valid as well for collections if it can be used in all other cases

## Accepted answer by luzzodev (CONTRIBUTOR)

Hello @bartlomiejgoralrtb,
you are mixing typings.
The supported form is the following, and is working as expected in your case.

``` python
app = FastAPI()

class QueryModel(BaseModel):
    descriptions: Annotated[list[str] | None, MinLen(1)] = None

@app.get("/test")
def test(query: Annotated[QueryModel, Query()]):
    return {"descriptions": query.descriptions} 
```
Ref: [Query Param Model]( https://fastapi.tiangolo.com/tutorial/query-param-models/?h=query), [Annotated Q Parameter](https://fastapi.tiangolo.com/tutorial/query-params-str-validations/#use-annotated-in-the-type-for-the-q-parameter)
