### Example Code

```python
from fastapi import Depends, FastAPI, Request
from fastapi.encoders import jsonable_encoder
from fastapi.responses import JSONResponse
from fastapi.security import APIKeyHeader
from starlette.exceptions import HTTPException

def http_exception_handler(request: Request, exc: HTTPException) -> JSONResponse:
    return JSONResponse(
        jsonable_encoder({
            "success": False,
        }),
        status_code=exc.status_code,
    )

app = FastAPI(
    exception_handlers={
        HTTPException: http_exception_handler,
    },
    dependencies=[Depends(APIKeyHeader(name="keykey"))]
)

@app.get("/")
def root() -> dict[str, str]:
    return {"ping": "pong"}
```


### Description

This codes runs as expected, with the exception handler being executed when you, for example, don't pass the Header.

However, my type checker (VSCode's default one, Pylance/Pyright, I think) gives me a type mismatch on the `exception_handlers` argument of FastAPI. Indeed, the argument is typed as an optional `dict` with the value type being `Callable[[Request, Any], Coroutine[Any, Any, Response]]`, which is incompatible with my handler. But should it?

As far as I know, that would be the annotation for an `async` handler, and indeed declaring my handler as `async` removes the mismatch. But given that passing a synchronous handler works, I believe that the typing for the dict value should be adjusted to `Callable[[Request, Any], Union[Response, Coroutine[Any, Any, Response]]]`

## Accepted answer by YuriiMotov (MEMBER)

Yes, you are right. Typing is incorrect for `exception_handlers` parameter. It should accept both `sync` and `async` handlers.

But, making your exception handler function `async` should be the first choice (if you don't have heavy computations or other blocking calls).
If you use `sync` function as exception handler, it will be run using `run_in_threadpool` and that's less efficient.
