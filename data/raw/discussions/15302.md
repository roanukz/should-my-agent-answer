### Example Code

```python
import warnings
from fastapi import FastAPI
from fastapi.encoders import jsonable_encoder
from fastapi.testclient import TestClient
from pydantic import BaseModel

# --- Issue 1: jsonable_encoder crashes on circular references ---
# Reported in #2972, #1891, Discussion #10358, Discussion #5973

class Node:
    pass

a = Node()
b = Node()
a.child = b
b.parent = a

try:
    jsonable_encoder(a)
    print("BUG: no error raised")
except RecursionError as e:
    print(f"CONFIRMED: RecursionError — {type(e).__name__}")
    print(f"  (no useful message, just stack exhaustion)")

# --- Issue 2: response_model_exclude accepted but has no effect ---
# Related to Discussion #13859

with warnings.catch_warnings(record=True) as w:
    warnings.simplefilter("always")

    app = FastAPI()

    class User(BaseModel):
        name: str
        password: str

    @app.get("/user", response_model_exclude={"password"})
    async def get_user():
        return User(name="alice", password="secret123")

    client = TestClient(app)
    response = client.get("/user")
    body = response.json()
    print(f"Response body: {body}")
    print(f"Password leaked: {'password' in body}")
    print(f"Warnings emitted: {len(w)}")
    if not w:
        print("  CONFIRMED: zero warnings — exclude silently accepted")
```

### Description

Two cases where FastAPI could catch problems early, consistent with how it already validates request parameters and response models.

**1. `jsonable_encoder` crashes on circular references**

Objects with bidirectional relationships (common in SQLAlchemy with `backref`, MongoEngine) cause `RecursionError` or fatal stack overflow with no clear message. This has been reported multiple times since 2021:
- #2972 (SQLAlchemy mapper recursion)
- #1891 (fatal stack overflow)
- Discussion #10358 (asks for "Circular reference detected" like json.dumps)
- Discussion #5973 (stack overflow on cyclical references)

`jsonable_encoder` could track visited objects and raise a clear `ValueError` on cycle detection, plus a depth bound for extremely deep structures.

**2. `response_model_exclude` / `response_model_include` accepted without effect**

When set on a route without an explicit `response_model`, these filters are accepted but never applied. A developer sets `response_model_exclude={"password"}` believing the field is filtered — it isn't. Related to Discussion #13859 where `response_model_exclude_none=True` is similarly accepted without effect.

A `UserWarning` at route registration when these are set but no `response_model` is active would catch the misconfiguration early.

**Context**

I found these by scoring each assumption FastAPI's code makes against how strongly it's enforced — unguarded, convention, runtime check, or type-level guarantee. Writing out the serialization dispatch and route configuration as explicit decision trees made these gaps visible. The invariant analysis methodology — how each assumption is scored and what "enforced" means at each level — is documented at github.com/savarin/lean-agent.

I have working implementations for both and would be happy to open PRs if these are things the team wants to address. They're independent changes (different files, different subsystems), so they'd be separate, focused PRs.
