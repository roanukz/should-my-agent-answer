## Accepted answer by PrasanthKumarS777 (NONE)

Great question! Here's a clear breakdown of class-based middleware in FastAPI/Starlette:

## Class-Based Middleware — Two Approaches

### 1. Pure ASGI Middleware (using `__init__` and `__call__`)
This is the lower-level approach:

from starlette.types import ASGIApp, Receive, Scope, Send

class AuthMiddleware:
    def __init__(self, app: ASGIApp):
        self.app = app

    async def __call__(self, scope: Scope, receive: Receive, send: Send):
        if scope["type"] == "http":
            # your auth logic here
            token = dict(scope.get("headers", [])).get(b"authorization", b"").decode()
            if not token:
                # reject request
                pass
        await self.app(scope, receive, send)

### 2. BaseHTTPMiddleware (using `dispatch`)
This is the higher-level, easier approach:

from starlette.middleware.base import BaseHTTPMiddleware
from starlette.requests import Request

class AuthMiddleware(BaseHTTPMiddleware):
    async def dispatch(self, request: Request, call_next):
        token = request.headers.get("authorization")
        if not token:
            return Response("Unauthorized", status_code=401)
        response = await call_next(request)
        return response

## When to use which?
- Use `dispatch` (BaseHTTPMiddleware) → simpler, cleaner, recommended for most use cases
- Use `__call__` (Pure ASGI) → better performance, needed for WebSockets or streaming

## Register in FastAPI:
app.add_middleware(AuthMiddleware)
