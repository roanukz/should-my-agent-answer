### Description

While reading fastapi/_compat, I noticed a small detail.

The continue seems unnecessary (no code after it in the loop body). This could be simplified (and short-circuited) without changing behavior, e.g.:
- return any(is_bytes_sequence_annotation(arg) for arg in get_args(annotation))
- or an early-return loop.

Is there any historical or compatibility reason to keep the current pattern?

## Accepted answer by ArmanShirzad (NONE)

**Short answer:** There is no behavioral difference here. The `continue` is redundant because the loop body does nothing after it. This can be simplified to an early return or to `any(...)`, which also short-circuits.

#### Why it is safe

* The recursive call has no side effects.
* Current code scans all union args and accumulates a boolean. Returning early or using `any(...)` preserves semantics while avoiding extra recursion.
* This pattern matches similar helpers that already use comprehension utilities.

#### Optional alternative (early return loop)

```python
if origin in (Union, UnionType):
    for arg in get_args(annotation):
        if is_bytes_sequence_annotation(arg):
            return True
    return False
```

#### Compatibility note

`UnionType` handles the `|` syntax on Python 3.10+. The change does not affect that logic. No API changes, only a local readability and micro-perf improvement.
