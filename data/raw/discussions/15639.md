### Example Code

```python
from fastapi import APIRouter, FastAPI

app = FastAPI()

users_router = APIRouter(prefix="/users", tags=["users"])


@users_router.get("/{user_id}")
def read_user(user_id: str):
    return {"user_id": user_id}


items_router = APIRouter(prefix="/{user_id}/items", tags=["items"])


@items_router.get("/{id}")
def read_item(user_id: str, id: str):
    return {"user_id": user_id, "id": id}


users_router.include_router(items_router)

app.include_router(users_router)
```


### Description

In this example, I'm using nested routers by calling `include_router` on a parent router. It's convenient to avoid repetition of the prefix of the parent one.

Is there a way to avoid duplication of the `Read Item` endpoint in the docs (ie. Swagger UI)? This endpoint appears twice, in both the `users` and `items` section.

I know it's possible to avoid the repetition by providing the `tags` to individual endpoints instead of doing it at the router level but it will be a bit tedious when adding more endpoints.

## Accepted answer by yudin-s (NONE)

This is expected from how FastAPI combines router metadata. Tags from the parent router and the child router both end up on the nested operation, and Swagger UI shows an operation under every tag it has. So your item route is not duplicated as a route, it is displayed in both tag groups.

There is not a clean switch that means "inherit the parent prefix but not the parent tags" for only the nested router. The usual workaround is to split the prefix-only grouping router from the tagged routers:

```python
from fastapi import APIRouter, FastAPI

app = FastAPI()

# Prefix-only router. No tags here.
users_prefix = APIRouter(prefix="/users")

users_router = APIRouter(tags=["users"])

@users_router.get("/{user_id}")
def read_user(user_id: str):
    return {"user_id": user_id}

items_router = APIRouter(prefix="/{user_id}/items", tags=["items"])

@items_router.get("/{id}")
def read_item(user_id: str, id: str):
    return {"user_id": user_id, "id": id}

users_prefix.include_router(users_router)
users_prefix.include_router(items_router)

app.include_router(users_prefix)
```

That keeps the URL nesting but prevents the `items` endpoints from inheriting the `users` tag. If most routes under `/users` should be tagged `users`, then tagging individual direct user endpoints is the more explicit option.
