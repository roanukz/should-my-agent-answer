## Accepted answer by sachinh35 (NONE)

Sure, here's my 2 cents on this:
1. Without going into the specifics of why - all API frameworks, be it in Python, Java or any other programming language treat path parameters as mandatory. This is a contract in the OpenAI [spec](https://swagger.io/docs/specification/v3_0/describing-parameters/#required-and-optional-parameters) and that's how the internet works. This is not an issue in Fast API.
2. There are millions of people who are using OpenAPI for their production loads and I'm fairly certain that a lot of them are using the upsert operation without any issue. So this problem looks very specific to your code otherwise there would have been at least 10s of thousands of issues related to this on the repo. 

Getting back to your code - I think your upsert operation is fundamentally wired incorrectly and you always need the `user_id` as a path parameter. Instead of generating the `user_id` on the server side, your client should always feed in the `user_id`. If you want to generate the `user_id` on behalf of the client, then that's a `POST` operation altogether as it represents the creation of a new resource rather than an update or insertion of an existing one identified by a path parameter.
