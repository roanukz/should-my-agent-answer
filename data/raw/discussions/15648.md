# format_sse_event() does not validate event/id fields, allowing SSE protocol injection

Discussion #15648 · 2026-05-30T15:56:00Z · https://github.com/fastapi/fastapi/discussions/15648

## Question

## Problem

PR #15588 added validation to `ServerSentEvent` so that multi-line values for `event` and `id` are rejected. However, the public `format_sse_event()` function in `fastapi.sse` does not apply those same checks.

This means a caller who passes user-supplied data directly to `format_sse_event()` can unintentionally inject arbitrary SSE fields:

```python
from fastapi.sse import format_sse_event

# attacker-controlled input
format_sse_event(event="legit\ndata: injected", data_str="safe")
# produces: b'event: legit\ndata: injected\ndata: safe\n\n'
```

The extra data: injected line was never intended — it is a protocol injection caused by the missing newline check.

Proposed fix
Reuse the existing _check_event_single_line and _check_id_valid helpers at the top of format_sse_event, the same way ServerSentEvent uses them. This makes both entry points enforce identical rules.

The change is two lines added to fastapi/sse.py and eight new parametrised tests in tests/test_sse.py (covering \n, \r, \r\n, and \0). All existing tests continue to pass.

Question
Would a PR with this fix be welcome?

## Accepted answer by YuriiMotov (MEMBER)

@hemanthvnp, thanks for your patience!

`format_sse_event` is not documented, therefore it should be considered as internal utility function.
The only one place where it's used with `id` and `event` parameters passed into it is
https://github.com/fastapi/fastapi/blob/afe41126f624af30038cc8e17b2aaf60ebd4b838/fastapi/routing.py#L518-L538

.. and the values of `item.event` and `item.id` are already validated as they come from the instance of `ServerSentEvent`.

So, adding this validation to `format_sse_event` would be redundant.
