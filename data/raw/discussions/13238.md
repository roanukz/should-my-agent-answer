### Example Code

```python
import logging
from typing import Annotated, AsyncGenerator

from anyio import open_file
from fastapi import Depends, FastAPI


async def get_thingy() -> AsyncGenerator[str, None]:
    """Should return a thingy, but is a badly behaved dependency, does nothing"""
    try:
        async with await open_file("/path/to/aintnosuchfileyo.txt", "r") as f:
            yield await f.read()
    except Exception:
        logging.warning("Ain't no such file yo!")


app = FastAPI()


@app.get("/")
async def root(thingy: Annotated[str, Depends(get_thingy)]):
    return {"message": f"Hello {thingy}"}
```

Not sure if this is related to the Python core issue [Worse error from asynccontextmanager in Python 3.10](https://bugs.python.org/issue45996), which, from a quick Google search, was the only relevant discussion that I could find.

Would be great if FastAPI could catch that `RuntimeError: generator didn't yield` , and instead raise something more useful, ideally an error message that identifies the dependency responsible for the underlying error. Possibly a custom middleware could catch and re-raise that error too? Not sure, it might need to happen inside `solve_dependencies()` , where the currently-being-solved dependency is available as a variable.

## Accepted answer by luzzodev (CONTRIBUTOR)

Hello @Jaza, 

about the traceback and your error, this is because the generator is no yielding anything due the exception occurring. You are no able to see what exception is because your generator does not re-raise the error.

Please read [Dependencies with yield and except](https://fastapi.tiangolo.com/tutorial/dependencies/dependencies-with-yield/#dependencies-with-yield-and-except).

Hope this helps.
