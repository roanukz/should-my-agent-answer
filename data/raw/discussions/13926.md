### Example Code

```python
from typing import Annotated

from fastapi import FastAPI, Form

from pydantic import BaseModel, Field

app = FastAPI()

class FormModel(BaseModel):
   id: Annotated[int, Field(None, exclude=True)] # doesnt work
   name: Annotated[str, Field(None)]

class FormDisplayModel(BaseModel):
   id: int = Field(None, exclude=True)
   name: str = Field(None)
@app.post("/")
def my_post(form:Annotated[FormModel, Form()]) -> FormDisplayModel:
   print(form)
   return form
```


### Description

it seems very inconsistent that when you use exclude=True on a display side that it doesnt include the field yet when you do the same on the form model it still includes it in the docs. as in the form still renders with a form field for id from the example above.

im aware of the way to make fields private with an underscore on the form side but that makes it a private field on the object. or to use 2 objects and inheritance as in have the 'pass it' through object has the hidden fields but then you would have to dump the form then re populate your pass through model. 

for the same reasons why a solution of "add an underscore to the schema model to hide a field" isnt the right answer the same applies to the form model in my opinion. 

a big use-case here would be to be able to pass the form object to the service layer but to add in values from the router dependencies as in user.id. you dont want the docs asking the user to be able to specify the user id

```
class FormModel(BaseModel):
   user_id: Annotated[int, Field(None, exclude=True)]
   name: Annotated[str, Field(None)]

class FormDisplayModel(BaseModel):
   user_id: int = Field(None, exclude=True)
   name: str = Field(None)

def my_post(form:Annotated[FormModel, Form()], user: CurrentUser) -> FormDisplayModel:
   form.user_id = user.id
   print(form)
   return form

```

inconsistencies in a library as large as fastapi should be viewed in the same light as a bug IMO

## Accepted answer by YuriiMotov (MEMBER)

You can call it "Bad design" or "Not intuitive behavior\design" of Pydantic, but as it's not stated anywhere that `exclude` should work for validation (affect validation schema), we can't call it "BUG".

As for solution to your task.
I think you should just exclude `user_id` from `FormModel` and create an instance of other (extended) class inside the endpoint (or dependency) passing input data to it:

```py
from typing import Annotated

from fastapi import FastAPI, Form
from pydantic import BaseModel, Field

app = FastAPI()

class FormModel(BaseModel):
    name: Annotated[str, Field(None)]

class FormDisplayModel(BaseModel):
    id: int = Field(None, exclude=True)
    name: str = Field(None)

@app.post("/")
def my_post(form: Annotated[FormModel, Form()]) -> FormDisplayModel:
    item = FormDisplayModel(id=1, name=form.name)
    print(item)
    return item
```

Or the approach with private attribute that you have already mentioned:
```py
from typing import Annotated

from fastapi import FastAPI, Form
from pydantic import BaseModel, Field

app = FastAPI()

class FormModel(BaseModel):
    _user_id: int | None = None
    name: Annotated[str, Field(None)]

@app.post("/")
def my_post(form: Annotated[FormModel, Form()]) -> FormModel:
    form._user_id = 1
    print(form)
    return form

```
