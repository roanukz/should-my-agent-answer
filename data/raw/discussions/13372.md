### Example Code


### Description

In any project that supports `fastapi dev main.py`, if you add a print line to the main.py, you'll find that the print in the main.py will be run twice.

This is a major issue; if the app route includes dynamic imports, it will cause the route to be included twice.

Please note: https://stackoverflow.com/questions/64003384

## Accepted answer by luzzodev (CONTRIBUTOR)

Hello @wu-clan, @JavierSanchezCastro, the problem is not fastapi-cli neither in uvicorn.

This has to deal with how uvicorn import modules, when you pass a string as argument. Under the hood `the importlib.import_module` is used and in your example this is what is happening.

``` python
# main.py
from fastapi import FastAPI
import uvicorn

app = FastAPI()

print("Hello!")

if __name__ == "__main__":
    uvicorn.run("main:app", host="0.0.0.0", port=8000)
```

The first time you load the main.py the module name is not `main` but ` __main__`, so in the import cache will be set the module `__name__`.
At this point your execution will arrive at 
`uvicorn.run("main:app", host="0.0.0.0", port=8000)`

Uvicorn will use `importlib.import_module`

`importlib.import_module("main")` -> but main is not the import cache so will loaded and thats why you see double print.

You can test using this code

``` python
from fastapi import FastAPI
import uvicorn

app = FastAPI()

print("Hello!", __name__)

if __name__ == "__main__":
    uvicorn.run("uvi_rerun:app", host="0.0.0.0", port=8000)
```

At this point you can fix your code structure and your code, knowing what is happening.
