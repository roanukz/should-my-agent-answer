### Example Code

```python
"""
Tests the code for minimal working example for
Optional Query Parameters with a Pydantic Model
"""

from typing import Annotated, Any

import pytest
from fastapi import FastAPI, Query
from pydantic import BaseModel, Field
from starlette import status
from starlette.testclient import TestClient


class FilterParams(BaseModel):
    a: int | None = Field(default=None)


app = FastAPI()


@app.get(path="/items", response_model=FilterParams)
def get_example(filter_query: Annotated[FilterParams, Query()]):
    return filter_query.model_dump(exclude_unset=True)


@pytest.fixture
def client_with_app():
    return TestClient(app)


@pytest.mark.parametrize(
    argnames="params",
    argvalues=[
        {"a": None},  # fails with 422 status code, "unable to parse string as integer"
        {},  # fails because missing optional param becomes part of model_fields_set
        {"a": 1},
    ],
)
def test_trading_group_response_units_are_sorted(
    client_with_app, params: dict[str, int | None]
):
    response = client_with_app.get("/items", params=params)
    assert response.status_code == status.HTTP_200_OK, response.text
    assert response.json() == params
```


### Description

I based my code on the example provided in the FastAPI docs for [Query Parameters with a Pydantic model]( https://fastapi.tiangolo.com/tutorial/query-param-models/?h=pydantic+qu#query-parameters-with-a-pydantic-model). You can remove the starlette and pytest imports to strip the example even more, but I assume it might be helpful.

My expectation is that FastAPI converts the optional query parameter correctly to a pydantic model with the property `model_fields_set` populated based on whether the parameter is missing or not.

## Accepted answer by luzzodev (CONTRIBUTOR)

Regarding your first point:

The current behavior is validated by Pydantic, and there is no equivalence between `None` and an empty string. This convention may be useful for your specific use case, but it could be completely inappropriate in other contexts.

Regarding the second point:

If the current example is not detailed enough to represent your issue, please provide a more complete one.
In any case, you can keep the current logic:

```python
@app.get(path="/items", response_model=FilterParams, response_model_exclude_unset=True)
def get_example(filter_query: Annotated[FilterParams, Query()]) -> dict:
    return filter_query.model_dump(exclude_unset=True)
```

Alternatively, you can omit both the parameters and the response model entirely from the route decorator.
