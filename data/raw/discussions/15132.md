### Example Code

from fastapi import FastAPI, Request
from starlette.routing import get_route_path

root_app = FastAPI()
sub_app = FastAPI()

root_app.mount("/subapp", sub_app)

@root_app.get("/test")
async def root_test(path: str, request: Request):
    return {
        "app": "root",
        "root_path": request.scope.get("root_path", ""),

### Description

I am creating a FastAPI application that is served behind a proxy which strips part of the path, so I've been following the [Proxy with a stripped path prefix](https://fastapi.tiangolo.com/advanced/behind-a-proxy/#proxy-with-a-stripped-path-prefix) docs. I am also using mounted sub-applications to handle API versioning (e.g. mounted at `/v1` and `/v2` for separate docs).

Initially, I was using the `root_path` parameter in the FastAPI constructor to configure the stripped-path prefix, which works as expected for the root application, but I experienced unexpected behaviour adding the sub-applications.

---

`tl;dr` According to the [FastAPI docs](https://fastapi.tiangolo.com/advanced/behind-a-proxy/#setting-the-root-path-in-the-fastapi-app):
> Passing the `root_path` to `FastAPI` would be the equivalent of passing the `--root-path` command line option to Uvicorn or Hypercorn.

However, my experience has shown that these configuration methods result in different behaviour for the request scope `path` which seems to break route matching in mounted sub-applications when using the `root_path` parameter.

## Accepted answer by YuriiMotov (MEMBER)

> Passing the `root_path` to FastAPI would be the equivalent of passing the `--root-path` command line option to Uvicorn or Hypercorn.

This statement in docs is not correct.
In fact, you should:
* use `--root-path` when you run app behind a proxy which **strips** part of the path
* use `root_path` parameter in the `FastAPI` constructor when you run app behind a proxy that **doesn't strip** part of the path

I opened PR to fix docs: https://github.com/fastapi/fastapi/pull/14238
