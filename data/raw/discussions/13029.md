### Example Code

```python
# ALTERNATIVE 1: LIFESPAN STATE
from contextlib import asynccontextmanager
from fastapi import FastAPI, Request
from motor.motor_asyncio import AsyncIOMotorClient


@asynccontextmanager
async def lifespan(app):
    mongo_client = AsyncIOMotorClient("mongo://")
    mongo_db = mongo_client["mydb"]
    yield {"db": mongo_db}
    mongo_client.close()


app = FastAPI(lifespan=lifespan)


@app.get("/")
async def root(request: Request):
    return request.state.db


# ALTERNATIVE 2: DEPENDENCY INJECTION
from contextlib import asynccontextmanager
from fastapi import FastAPI, Depends
from motor.motor_asyncio import AsyncIOMotorClient, AsyncIOMotorDatabase

mongo_client = None

def init_db():
    global mongo_client
    mongo_client = AsyncIOMotorClient("mongo://")

def get_db():
    return mongo_client["mydb"]

def close_db():
    mongo_client.close()
    


@asynccontextmanager
async def lifespan(app):
    init_db()
    yield
    close_db()


app = FastAPI(lifespan=lifespan)

    
@app.get("/")
async def root(db: Annotated[AsyncIOMotorDatabase, Depends(get_db)]):
    return db
```


### Description

I have FastAPI with MongoDB connected via Motor. I open a MongoDB connection at the beginning of an app and close it at the end using lifespan. 

Since I initialize the client inside lifespan, I cannot use dependency injection to `get_db()` without using global variables. But global variables are highly discouraged in Python.

On the other hand, I cannot help but feel weird to pass database client to Request state and hold it with every request.

So, my question is: how appropriate is it to hold such a sensitive information about database client in requests and tag it along with every request all the time? 

A related question is: does `request.state`mean that all values passed to it are tagged along with each request?

Dependency injection seems more appropriate for this use case but it practically requires global variables (unless I use some ORM which would store a reference to the database for me).

Please help me understand the best practice here!

Thank you!

## Accepted answer by YuriiMotov (MEMBER)

I tend to use first approach (with `request.state.db`).

I don't see any problems in having `db` in state for every request. It will only contain reference to that object.
