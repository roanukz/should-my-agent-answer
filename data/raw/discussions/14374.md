## Accepted answer by JunjieAraoXiong (NONE)

Hi @gbertoncelli-nw,

The `objgraph` trace pointing to `run_in_threadpool` is the key indicator here.

**The likely cause**
When you loop through the file with `await input_file.read(CHUNK_FILE_SIZE)`, you are dispatching a new task to the threadpool for *every single chunk*. For a large file, this creates thousands of short-lived thread tasks. This puts immense pressure on the `anyio` and `starlette` threadpool and the Python Garbage Collector, often leading to memory fragmentation or "soft leaks" where objects (like the captured `self.file` reference in the thread task) stay alive longer than expected.

**Solution**
Since `UploadFile` wraps a synchronous `SpooledTemporaryFile`, it is most efficient to perform the file copy completely synchronously within a *single* threadpool task, rather than switching back and forth between async and sync contexts for every chunk.

Try replacing your read/write loop with `shutil.copyfileobj` wrapped in `run_in_threadpool`. This moves the heavy lifting to a worker thread and keeps the main loop clean.

```python
import shutil
from starlette.concurrency import run_in_threadpool

# Define a sync helper function to do the copy
def save_file_sync(input_file_obj, output_path):
    with open(output_path, "wb") as buffer:
        shutil.copyfileobj(input_file_obj, buffer)

# Inside your endpoint
for input_file in setup_files:
    output_path = Path('sample_folder') / some_random_name()
    
    # Ensure the file cursor is at the start (just in case)
    await input_file.seek(0)
    
    # Run the blocking copy operation in a separate thread
    await run_in_threadpool(save_file_sync, input_file.file, output_path)
```

**your questions**

**Is `FormData` or `UploadFile` memory leaking?**
    Likely not the classes themselves, but the *usage pattern* involving thousands of `run_in_threadpool` calls creates references that are hard for the GC to clean up immediately. The `objgraph` references you see are likely the closures created for these thread tasks.

**Is it correct to use `list[UploadFile]`?**
    Yes, your annotation `Annotated[list[fastapi.UploadFile], fastapi.File()]` is correct. `python-multipart` handles this standardly.

*Should I care to handle closing other resources?**
    Your `UploadFilesContext` is excellent practice. However, if you switch to the `shutil` method above, you might find the manual closing is still necessary but the memory pressure will disappear because you aren't generating the massive object overhead during the read.
