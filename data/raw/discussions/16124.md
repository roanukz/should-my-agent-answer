### Example Code

```python
import typing as t

import fastapi
import fastapi.testclient
from pydantic import AliasChoices, BaseModel, Field


class Model(BaseModel):
    items: t.Annotated[list[str], Field(validation_alias=AliasChoices("items_alias", "items"))]


app = fastapi.FastAPI()


@app.get("/")
def root(
    model: t.Annotated[Model, fastapi.Query()],
) -> Model:
    return model


client = fastapi.testclient.TestClient(app)


def request_with_params(params: dict):
    result = client.get("/", params=params)
    assert result.status_code == 200, (result.status_code, result.json())


request_with_params({"items": "asdf"})
request_with_params({"items_alias": ["asdf", "asd2"]})
request_with_params({"items_alias": "asdf"})  # <-- this one fails
```


### Description

I've created a Query-Model that contains a list field, so that the field may be provided in multiple times. I want to provide multiple aliases for this field. When I provide the field under the default name, all is well. When I provide multiple values under the alias, all is well. However, when I provide a single value under the alias, I get a validation error.

I would expect the validation to succeed with a single value under the alias name

## Accepted answer by YuriiMotov (MEMBER)

`AliasChoices` for Query \ Form \ Header \ Cookie parameters is not currently supported due to limitation of OpenaAPI standard - as far as I know, there is no way to declare aliases for request parameters in OpenAPI
