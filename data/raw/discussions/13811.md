### Example Code

```python
from fastapi import FastAPI, Depends, HTTPException
from typing import Annotated
from pydantic import BaseModel

app = FastAPI()

class TokenModel(BaseModel):
    token: str

def token_dep(token: str) -> TokenModel:
    if token != "valid":
        raise HTTPException(status_code=400, detail="Invalid token")
    return TokenModel(token=token)

# This works
TokenDep = Annotated[TokenModel, Depends(token_dep)]

@app.get("/ok")
def ok_route(dep: TokenDep):
    return dep

# This breaks
type TokenDepType = Annotated[TokenModel, Depends(token_dep)]

@app.get("/fail")
def fail_route(dep: TokenDepType):
    return dep
```


### Description

I’m experimenting with Python 3.12 and the new [type alias syntax from PEP 695](https://peps.python.org/pep-0695/). I’m running into an issue when combining it with FastAPI’s dependency injection and Pydantic models.

Using `Annotated[Model, Depends(func)]` with a regular assignment works fine. But when I replace it with a type alias, it silently fails and produces a 422 Unprocessable Entity if the dependency returns a Pydantic model. Without Pydantic, it behaves as expected.
