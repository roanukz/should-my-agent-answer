### Description

FastAPI automatically returns a 404 Not Found response when accessing an unknown route. However, this does not raise an exception, meaning observability tools like Honeycomb do not capture it as an error.

This behavior makes it difficult to track unexpected requests to missing routes, especially when debugging API clients or unexpected traffic patterns.

## Steps to Reproduce:

1. Create a simple FastAPI app
```
from fastapi import FastAPI

app = FastAPI()

@app.get("/hello")
def read_hello():
    return {"message": "Hello World"}
```

2. Start the application and access a non-existent endpoint:
```
curl -i http://127.0.0.1:8000/items/
```

3. The response will be:
```
HTTP/1.1 404 Not Found
content-type: application/json
{"detail": "Not Found"}
```

4. However, Honeycomb does not report this as an error.

## Expected Behavior:

FastAPI could provide an option to raise an exception when a 404 Not Found response occurs due to a missing required path parameter. This would allow observability tools like Honeycomb to capture these cases as errors instead of treating them as normal responses.


Would this be something FastAPI could consider addressing?

## Accepted answer by jgould22 (NONE)

FastAPI is unlikely to integrate something like this as it is best addressed in middle-ware. 

It looks like honeycomb recommends https://github.com/open-telemetry/opentelemetry-python which provides an instrumentation here https://github.com/open-telemetry/opentelemetry-python-contrib/tree/main/instrumentation/opentelemetry-instrumentation-fastapi
