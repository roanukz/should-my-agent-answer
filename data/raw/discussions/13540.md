### Example Code

```python
import shutil
from pathlib import Path

from fastapi import FastAPI, Query
from fastapi.responses import FileResponse, JSONReponse

app = FastAPI()

@app.get("/file")
async def download_file(file_name: str=Query(...)):
    file_path = Path(file_name)
    file_path_bak = file_path.with_name(f"{file_name}.bak")
    shutil.copy(file_path, file_path_bak)
    return FileResponse(file_path_bak, headers={"Content-Disposition": f'attachment; filename="{file_name}"'})
```


### Description

Hello, I want to write a download server, so I wrote something above. At first, I didn't add `shutil.copy` because it worked well. However, recently I found that if I want to use httpx to download a file that may being written when it was downloaded (for example, a log file, if the log file would log that itself would be downloaded), httpx would raise error like "httpx.RemoteProtocolError: peer closed connection without sending complete message body (received 0 bytes, expected 8725)"

So I think I can copy the log  file before it is downloaded, and delete the backup log file after it is downloaded. But I don't know how to promise it to be removed after downloading finished. I found [BackgroundTasks Dependency Injection](https://fastapi.tiangolo.com/tutorial/background-tasks/#dependency-injection) might satisfy my requirement, as it says `In this example, the messages will be written to the log.txt file after the response is sent.` with an italic <i>"after"</i>. But back to my case, I'm not sure how to use it. In fact, I don't quite understand what `q` in the code exactly means. In my case, if I want to use it, should I write
```python
def delete_bak(bak_file:Path):
    bak_file.unlink()


def get_query(background_tasks: BackgroundTasks, q: Path| None = None):
    if q:
        background_tasks.add_task(delete_bak, q)
    return q


@app.get("/file")
async def download_file(
   background_tasks: BackgroundTasks, q: Annotated[str, Depends(get_query)], file_name: str=Query(...)
):
    file_path = Path(file_name)
    file_path_bak = file_path.with_name(f"{file_name}.bak")
    shutil.copy(file_path, file_path_bak)
    background_tasks.add_task(delete_bak, file_path_bak)
    return FileResponse(file_path_bak, headers={"Content-Disposition": f'attachment; filename="{file_name}"'})
```
Am I right to do this way?

## Accepted answer by marsboy02 (NONE)

q represents an optional query parameter. For example, in the case of reference you send.  if a client makes a request like:

```bash
/send-notification/{email}?q=some_query
```

then q is present. In this case, according to the reference you provided, here's what happens:

1. A background task is scheduled to write the "message to email" line into log.txt.
2. Then, another background task is scheduled to write the line "found query: some_query" into log.txt.
3. Because log.txt is opened in append mode, once the API response is returned, the background tasks run sequentially and both messages are appended to the log.

As mentioned, q is an optional query parameter. Consider the following example:

```bash
/send-notification/{email}
```

In this case, if no query parameter is provided, get_query doesn’t add any extra task, so only "message to email" is logged.
Now, let’s apply similar logic to a /file endpoint with a request like /file?q=some_path. The following logic would occur:

1. A backup copy of the file is created (with a .bak extension).
2. A background task is scheduled to delete the backup copy.
3. Since an optional query parameter is provided (q=some_path), another background task is scheduled to delete some_path.
4. After the API returns its response, the remaining tasks in the background queue execute.

This behavior might seem odd—it suggests that the optional query parameter might not be necessary. Without knowing all the details of the request and response requirements, it’s hard to say definitively, but I hope this explanation helps. Have a great day!
