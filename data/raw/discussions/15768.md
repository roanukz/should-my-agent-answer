### Description

I'm integrating with a HTTP client that is posting form data, I receive a request like this:

```
POST /Action HTTP/1.1\r
Host: localhost
Content-Type: text/html
\r
&Source=hello&other=thing
```

I think fastapi isnt interpreting this correctly due to the legacy content type, and Source is coming out null

Is there a good workaround for this?

## Accepted answer by YuriiMotov (MEMBER)

I think you can workaround this using Middleware that fixes the `Content-Type`:

```py
from fastapi import FastAPI, Form

app = FastAPI()


class FixContentTypeMiddleware:
    def __init__(self, app):
        self.app = app

    async def __call__(self, scope, receive, send):
        if scope["type"] == "http" and scope["path"] == "/Action":
            headers = [
                (name, value)
                for name, value in scope["headers"]
                if name != b"content-type"
            ]
            headers.append((b"content-type", b"application/x-www-form-urlencoded"))
            scope = dict(scope, headers=headers)
        await self.app(scope, receive, send)


app.add_middleware(FixContentTypeMiddleware)


@app.post("/Action")
async def process(Source: str = Form(...)):
    return {"Source": Source}

```
