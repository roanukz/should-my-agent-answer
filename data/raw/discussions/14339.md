### Additional Context

So I created a function to call openAI api as a synchronization request. The length of the message you send the request takes time to respond (for a few seconds). If I run this server as uvicorn and send the request to that function and send the request one more time before the response comes, can server use the method in the next request after the previous response ends?

## Accepted answer by YuriiMotov (MEMBER)

As your function is `async` and there is no any `await` inside it, it will be executed in one go without interruption.
So, your worker will only be able to handle 1 request at a time.

If you need to use blocking code in your endpoint functions (like you do in this code example), either convert this endpoint to sync (remove `async` from function signature) or use `run_in_threadpool` to run blocking code inside `async` function.

One more alternative (in your case better use on of the approaches above) is to make `client.beta.messages.create` async and add some `await asyncio.sleep(0)` inside it to let event loop execute other tasks.
