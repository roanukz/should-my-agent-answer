### Description

The name status feels quite generic and can easily conflict with local variables, function parameters, ORM model fields (e.g., status column), enums, or other modules in real-world projects.

For example, many applications have something like:

class Order(Base):
    status = Column(String)
    
In such cases, importing status from FastAPI can reduce clarity or cause shadowing/confusion in larger codebases.

Suggestion
Would it make sense to:
Rename it to something more explicit like HttpStatus
Or provide an alternative export such as:

from fastapi import http_status


Is there a design reason for keeping the name as status, and are there plans to make it less generic in future versions?

Thanks for the great work on FastAPI 🙌

You can always import it with `from fastapi import status as http_status`
