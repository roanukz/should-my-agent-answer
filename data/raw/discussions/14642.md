### Description

use axios to sent 2 request
```
["a","b"].map(item =>{axios.get(`/test/${item}`).then(v=>console.log(v.data))})
["a","b"].map(item =>{axios.get(`/test2/`).then(v=>console.log(v.data))})
```

server log is 
```
test receive web request!
test receive web request!
test func start  9936
test func start  16512
INFO:     127.0.0.1:60413 - "GET /test/a HTTP/1.1" 200 OK
INFO:     127.0.0.1:60412 - "GET /test/b HTTP/1.1" 200 OK
test2 receive web request!
test func start  9936
INFO:     127.0.0.1:60434 - "GET /test2/ HTTP/1.1" 200 OK
test2 receive web request!
test func start  9936
INFO:     127.0.0.1:60436 - "GET /test2/ HTTP/1.1" 200 OK
```
it's means : 
     when app.get have path arg , requests is parallel processing。
     when app.get no path arg, requests are being responded to one by one。

In reality, the test function is a database update feature and cannot be cached. This means that every time the test is executed, the results are different, even though the parameters have not changed.

My design is:  
When the first request for test2 is received, add test to background tasks to run, and immediately return 'The task has started running.'  
When test is already running and a test2 request is received, return 'The task is already running.'  

But the current situation: when multiple test2 requests are received, they end up running one after another in a queue.  

I have looked for official documentation but could not find relevant technical details. I am seeking help here.

## Accepted answer by walkinrain2008 (NONE)

serve is correct, it's a browser issue. 
I sent the request using the console in the Chromium Edge developer tools.
I went to Stack Overflow, and luckily, I guessed a few keywords for the search and found a related question from three years ago.
Among the many answers, I found a clue. The reason for this phenomenon is a browser issue. Any browser with the Chromium core may have this problem.

Conclusion:
Chromium will intercept the same GET requests and try to wait for the results to establish a cache. When connecting to 127 local, it may allow multiple requests to execute one by one because of the local client-server setup. When calling remotely, only one request remains.
At the same time, I rewrote the consecutive requests using Python and Node.js and got the expected results.

Stack Overflow really lives up to its reputation!
