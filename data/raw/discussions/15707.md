### Example Code

```python
from typing import Annotated

import uvicorn
from fastapi import Body, FastAPI
from pydantic import BaseModel, Field


class TestForm(BaseModel):
    public_field: Annotated[str, Field(min_length=3)]
    hidden_field: Annotated[str, Field(None, exclude=True)]


app = FastAPI(
    title="Test 2 API",
    version="1.0.0",
    docs_url="/docs",
    openapi_url="/openapi.json",
)


@app.post("/")
async def testing(form: TestForm = Body()):
    form.hidden_field = "im hidden"

    response = form.model_dump()

    return response


if __name__ == "__main__":
    uvicorn.run(
        "test2:app",
        host="127.0.0.1",
        port=8000,
        reload=True,
    )
```


### Description

open the docs at [/docs ](http://127.0.0.1:8000/docs) the swagger shows the "form" values as having 
<img width="326" height="244" alt="image" src="https://github.com/user-attachments/assets/c20bb3fb-0e96-4490-89ee-8235da3416bf" />
```
{
  "public_field": "aaa",
  "hidden_field": "bbb"
}
```

i understand that pydantic exclude=True is for "serialization" but its now being used as a input method so the rules are a bit blurred. it makes a lot more sense then that the exclude=True can be re used in this case to not show the value in docs / requestable from the route. 

there are times you want to request data from the user and then add on stuff in the route. like adding the user thats performing this action or route info to the DTO model without having to duplicate models everywhere. 

the work around on this is to have 2 models. 1 with the public fields and the other with combined private ones and to model_dump() the public into the "full" model but this feels like a duct tape solution. pydantic already has the setting exclude=True. its not serialization_exclude=True. basically when the model is used like `form: TestForm = Body()` to treat the context of "this model is now asking for form data" to then honor the exclude field. since doing a  model dump would kick in the serialization aspect and the hidden fields would be excluded then from output in anycase. 

what benefit is there having `exclude=True` still asking for the data from the user for that field? 

i presume something like form is a username/password field where the password would be exclude so it doesnt show in any logs etc. but i would venture to say that this is easy to work around rather than a large form item. 

suggestion to not having breaking changes would be to bring in a flag on `form: TestForm = Body(ignore_excluded=True)` (defaults to False). 

we have a few devs and this has always been seen as "confusing" amongst those ive spoken to that the exclude doesnt exclude the field in the docs.

## Accepted answer by PrashantSinghUP64 (NONE)

I would keep `exclude=True` as serialization-only and avoid putting server-populated values in the request schema.

For the use case you described, two patterns work pretty well.

If the field is part of your internal DTO/domain object, use a small input model and build the internal model in the route:

```python
from typing import Annotated
from fastapi import Body, Depends
from pydantic import BaseModel, Field

class TestFormIn(BaseModel):
    public_field: Annotated[str, Field(min_length=3)]

class TestFormInternal(TestFormIn):
    hidden_field: str

@app.post("/")
async def testing(
    form: Annotated[TestFormIn, Body()],
    user_id: str = Depends(get_current_user_id),
):
    dto = TestFormInternal.model_validate({
        **form.model_dump(),
        "hidden_field": user_id,
    })
    return dto.model_dump()
```

If the value is only route/runtime context and should never be validated or serialized as model data, use a Pydantic private attribute instead:

```python
from typing import Annotated
from fastapi import Body
from pydantic import BaseModel, PrivateAttr

class TestForm(BaseModel):
    public_field: str
    _hidden_field: str | None = PrivateAttr(default=None)

@app.post("/")
async def testing(form: Annotated[TestForm, Body()]):
    form._hidden_field = "set in route"
    return form.model_dump()
```

That keeps Swagger honest: fields shown in the request body are fields the client can actually send. I think changing `Field(exclude=True)` to mean "not part of input" only when used with `Body()` would make the same model behave differently depending on context, which is probably why the current behavior is confusing but consistent.
