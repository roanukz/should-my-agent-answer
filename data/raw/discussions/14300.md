### Example Code

```python
from typing import Annotated

from fastapi import FastAPI, Query
from pydantic import BaseModel, Json

app = FastAPI()


class FilterParams(BaseModel):
    state: str | None = None
    sku: str | None = None


@app.get("/case1")
async def case1(
    filter_query: Annotated[FilterParams, Query()] = FilterParams(),
) -> dict:
    """This shows individual query parameters in Swagger (state, sku)"""
    return {"filter": filter_query}


@app.get("/case2")
async def case2(
    filter_query: Annotated[FilterParams, Query()] = FilterParams(),
    filter_json: Annotated[Json[FilterParams] | None, Query(alias="filter")] = None,
) -> dict:
    """
    This shows filter_query as a map/object in Swagger (UNEXPECTED)
    Having the Json[FilterParams] parameter changes how filter_query is rendered.
    """
    return {"filter_query": filter_query, "filter_json": filter_json}


@app.get("/case3")
async def case3(
    filter_json: Annotated[Json[FilterParams] | None, Query(alias="filter")] = None,
) -> dict:
    """This shows filter as a JSON string parameter (EXPECTED)"""
    return {"filter": filter_json}


@app.get("/case4")
async def case4(
    filter_query: Annotated[Json[FilterParams], Query(alias="filter")],
) -> dict:
    """This shows individual query parameters in Swagger (state, sku) (UNEXPECTED?)"""
    return {"filter": filter_query}


if __name__ == "__main__":
    import uvicorn

    uvicorn.run(app, host="0.0.0.0", port=8001)
```


### Description

When using `Query()` with a Pydantic model alongside a `Json[Model]` parameter, the OpenAPI schema generation behaves inconsistently. The `Query()` model parameter shows as a **map/object** in Swagger when a `Json[Model]` parameter is present, but shows as **individual query parameters** when the `Json[Model]` parameter is removed.

## Environment

- FastAPI version: 0.115.0+
- Python version: 3.12
- Pydantic version: 2.x

## Observed Behavior

### Case 1: Query() only (`/case1`)

OpenAPI schema shows:
```json
{
  "parameters": [
    {
      "name": "state",
      "in": "query",
      "schema": {"type": "string"}
    },
    {
      "name": "sku",
      "in": "query",
      "schema": {"type": "string"}
    }
  ]
}
```

**Swagger UI**: Shows two separate input fields (state, sku) ✅ **EXPECTED**

### Case 2: Query() + Json[Model] (`/case2`)

OpenAPI schema shows:

  "parameters": [

      "name": "filter_query",
      "in": "query",

        "$ref": "#/components/schemas/FilterParams"

      "name": "filter",

      "schema": {

**Swagger UI**: Shows `filter_query` as a map/object input ⚠️ **UNEXPECTED**

## Accepted answer by YuriiMotov (MEMBER)

> The `Query()` model parameter shows as a **map/object** in Swagger when a `Json[Model]` parameter is present, but shows as **individual query parameters** when the `Json[Model]` parameter is removed.

This (combining query model with other query parameters) is currently not supported.
There is a PR that attempts to add such support: https://github.com/fastapi/fastapi/pull/12481

As for **case 4**, I looked at it only briefly, but it seems to me that the schema is good. Why do you think this is not expected?

In **case 3** the schema is quite general, but I think it can't be improved (as far as I know, there is no way to express such logic for query parameters in openapi)
