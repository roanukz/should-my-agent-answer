### Example Code

```python
import uvicorn
from fastapi import FastAPI, HTTPException
from fastapi.exceptions import RequestValidationError
from fastapi.responses import PlainTextResponse
from starlette.exceptions import HTTPException as StarletteHTTPException

app = FastAPI()


@app.exception_handler(StarletteHTTPException)
async def http_exception_handler(request, exc):
    return PlainTextResponse(str(exc.detail), status_code=exc.status_code)


@app.exception_handler(RequestValidationError)
async def validation_exception_handler(request, exc):
    return PlainTextResponse(str(exc), status_code=400)


@app.get("/items/{item_id}")

        raise HTTPException(status_code=418, detail="Nope! I don't like 3.")
```

### Description

Following the tutorial in [the docs page about overriding request validation exceptions](https://fastapi.tiangolo.com/tutorial/handling-errors/#override-the-default-exception-handlers) does not seem to produce the expected result.

I run the code provided (see my example) but do not get the output the docs suggest:

```

$ curl http://localhost:8000/items/foo
[{'type': 'int_parsing', 'loc': ('path', 'item_id'), 'msg': 'Input should be a valid integer, unable to parse string as an integer', 'input': 'foo'}]
```

The last command should produce a plain text response.

So far Just posting to see if others can reproduce this. If so, do the docs need updating?

## Accepted answer by luzzodev (CONTRIBUTOR)

@callumforrester based on the docs example, the closest and simple thing you can do is something like that

```  python
@app.exception_handler(RequestValidationError)
async def validation_exception_handler(request, exc: RequestValidationError):
    message = f"{len(exc.errors())} validation errors:\n"
    for err in exc.errors():
        error_type = err.get("type", "Unknown")
        error_location = err.get("loc", ("", ""))
        error_message = err.get("msg", "")
        message+="%s -> %s\n" % error_location
        message += f"  {error_message}  (type={error_type})\n"
    return PlainTextResponse(message, status_code=400)
```

```
1 validation errors:
path -> item_id
  Input should be a valid integer, unable to parse string as an integer  (type=int_parsing)
```

This is just a basic example and of course need to be more robusts than this in a real case scenario.
But at the end this show exactly what you can do with `@app.exception_handler`
