# ContextVars in sync vs async dependencies

Discussion #13382 · 2025-02-16T22:17:38Z · https://github.com/fastapi/fastapi/discussions/13382

## Question

## Summary

I have noticed some inconsistencies with the value of a `ContextVar`, and have managed to replicate a simple example below.

The TL;DR appears to be that FastAPI treats _synchronous_ dependencies in a separate thread to the one handling the request, thereby causing issues with the way `ContextVar` handles values internally. The same issue is _not_ present with asynchronous dependencies.

## Example Code

```python
from __future__ import annotations

import asyncio
import time
from contextvars import ContextVar
from random import randint
from typing import Annotated, Any

from fastapi import Depends, FastAPI

app = FastAPI()

test_var: ContextVar[str | None] = ContextVar("test_var", default=None)


def sf() -> tuple[str | None, str]:
    """
    Sync fixture to set `test_var`.
    """
    old_value = test_var.get()
    new_value = f"sf-{randint(0, 100):03d}"
    test_var.set(new_value)
    return old_value, new_value


async def af() -> tuple[str | None, str]:
    """
    Async fixture to set `test_var`.
    """
    old_value = test_var.get()
    new_value = f"af-{randint(0, 100):03d}"
    test_var.set(new_value)
    return old_value, new_value


@app.get("/sr-{id}")
def get_sr(id: int) -> dict[str, Any]:
    """
    Synchronous request with test_var.
    """
    old_value = test_var.get()
    test_var.set(f"sr-{id:03d}")
    sleep = randint(1, 5)
    time.sleep(sleep)
    return {
        "input": f"{id:03d}",
        "old": old_value,
        "new": test_var.get(),
        "sleep": sleep,
    }


@app.get("/ar-{id}")
async def get_ar(id: int) -> dict[str, Any]:
    """
    Asynchronous request with explicit test_var.
    """
    old_value = test_var.get()
    test_var.set(f"ar-{id:03d}")
    sleep = randint(1, 5)
    await asyncio.sleep(sleep)
    return {
        "input": f"{id:03d}",
        "old": old_value,
        "new": test_var.get(),
        "sleep": sleep,
    }


@app.get("/sr/sf")
def get_sr_sf(
    old_new: Annotated[tuple[str | None, None], Depends(sf)],
) -> dict[str, Any]:
    """
    Synchronous request with sync fixture.
    """
    old, new = old_new
    sleep = randint(1, 5)
    time.sleep(sleep)
    return {
        "old": old,
        "new": new,
        "test_var": test_var.get(),
        "sleep": sleep,
    }


@app.get("/sr/af")
def get_sr_af(
    old_new: Annotated[tuple[str | None, None], Depends(af)],
) -> dict[str, Any]:
    """
    Synchronous request with async fixture.
    """
    old, new = old_new
    sleep = randint(1, 5)
    time.sleep(sleep)
    return {
        "old": old,
        "new": new,
        "test_var": test_var.get(),
        "sleep": sleep,
    }


@app.get("/ar/sf")
async def get_ar_sf(
    old_new: Annotated[tuple[str | None, None], Depends(sf)],
) -> dict[str, Any]:
    """
    Asynchronous request with sync fixture.
    """
    old, new = old_new
    sleep = randint(1, 5)
    await asyncio.sleep(sleep)
    return {
        "old": old,
        "new": new,
        "test_var": test_var.get(),
        "sleep": sleep,
    }


@app.get("/ar/af")
async def get_arequest_sync(
    old_new: Annotated[tuple[str | None, None], Depends(af)],
) -> dict[str, Any]:
    """
    Asynchronous request with async fixture.
    """
    old, new = old_new
    sleep = randint(1, 5)
    await asyncio.sleep(sleep)
    return {
        "old": old,
        "new": new,
        "test_var": test_var.get(),
        "sleep": sleep,
    }


if __name__ == "__main__":
    import uvicorn

    test_var.set("init")

    uvicorn.run(app, host="localhost", port=8000)
```

You can see in the logs that:

- Simple requests with no dependencies (i.e., `/sr-{id}` and `/ar-{id}`) work fine irrespective of whether they are synchronous or not.
- Requests using the _async_ dependency (i.e., `/sr/af` and `/ar/af`) work fine. The value of `test_var` when retrieved is the same as what was set within the fixture.
- Requests using the _sync_ dependency (i.e. `/sr/sf` and `/ar/sf`) _do not_ see the `ContextVar` value set within the dependency propagate to the main request function.

On the one hand, I'm glad to see that the asynchronous dependencies behave well; a `ContextVar` that is updated within them is propagated to the main request and can be retrieved.

It seems clear to me though that the synchronous dependency don't behave as anticipated. I would have expected that being synchronous, there would be less of risk of having issues with the way `ContextVar` manages values, but FastAPI must be doing something that interferes here.

This bug is not critical, given that it can be circumvented using asynchronous dependencies, but I do think there should be either:

- A fix to the way synchronous dependencies are handled; or,
- An update to the docs warning about this (unless I have missed that)

## Accepted answer by jgould22 (NONE)

> The TL;DR appears to be that FastAPI treats synchronous dependencies in a separate thread to the one handling the request, thereby causing issues with the way ContextVar handles values internally. The same issue is not present with asynchronous dependencies.

This is not a bug, and is expected behaviour. FastAPI makes the assumption that a sync dependency has blocking code in it (otherwise why not use async) since FastAPI is an async first framework it spawns these dependencies onto a thread pool so as not to block the event loop. This will have implications for context vars.
