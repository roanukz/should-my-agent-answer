## Accepted answer by dolfinus (CONTRIBUTOR)

Requirements line: "starlette>=0.40.0,<0.51.0"

CVE affected versions: "starlette>= 0.39.0, <= 0.49.0"

As most of package managers prefer latest possible version during dependency resolution,  this will lead to installing 0.49.1 or 0.50.0 which are not affected by this CVE.

Cases then version with CVE is installed:
* Starlette version is limited by some other dependency
* Starlette version is explicitly limited by user
* Starlette was installed long time ago into venv, and no package updates were performed since

Releasing FastAPI with lower version limit bumped will not change anything in these 3 cases. If user wants to use specific Starlette version, of cannot upgrade, nothin will change.
It's not a FastAPI job to perform vulnerability scans or maintenance for dependencies used in user project.
