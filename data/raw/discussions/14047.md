### Example Code

```python
from enum import StrEnum
from typing import Annotated, TypeVar

from fastapi import FastAPI, Query
from pydantic import BeforeValidator

T = TypeVar("T")


def map_empty_to_null(val: T) -> T | None:
    if val == "":
        return None
    return val


GenericQuery = Annotated[Annotated[T, BeforeValidator(map_empty_to_null)], Query]


class Foo(StrEnum):
    A = "a"
    B = "b"
    C = "c"


app = FastAPI()


@app.get("/")
async def get_home(
    q: GenericQuery[str | None] = None,
    foo: GenericQuery[list[Foo] | None] = Query(default=None),
    bar: GenericQuery[list[Foo] | None] = None,
):
    return {"q": q, "foo": foo}


if __name__ == "__main__":
    import uvicorn

    uvicorn.run(app, host="0.0.0.0", port=8000)
```


### Description

My Understanding from above code
> In FastAPI, parameters are classified as query, path, or body depending on how they’re declared. Normally, adding Query(...) makes FastAPI treat it as a query param, while plain = None without Query defaults to body (for non-path args). given that, foo and bar should have same side effect.

Here, I wrapped the types in a reusable `GenericQuery` annotation. For `foo`, I still passed `Query(default=None)`, and FastAPI correctly treats it as a query param. For `bar`, I relied on the annotation alone, but FastAPI ignores it and incorrectly places bar in the request body

## Accepted answer by simone-trubian (NONE)

Hi @ManiMozaffar 

I suggest changing your `GenericQuery` signature to the following

```python
GenericQuery = Annotated[T, BeforeValidator(map_empty_to_null), Query()]
```

This signature has two improvements
1. You don't need to nest annotations, since the runtime will flatten it anyway, expanding the nested annotation into the outermost one.
2. It fixes your issue

The issue is caused by passing to FastAPI a _function_, while the proposed annotation passes it a Query object.

When initialising the API, FastAPI parses all the parameters of the endpoint functions, casting them as queries, path parameters, etc. When passing a Query object in a query annotation, FastAPI recognises it correctly easily. With your annotation, FastAPI discards the function and makes a best guess of what the parameter could be. As it happens `q` is parsed as a query, but `bar` is recognised as a body parameter because the data type is a list. `foo` on the other hand works as expected because you do pass to the parameter a `Query` object.

I tested the following endpoint with the modified annotation and it works as expected.

```python
@app.get("/")
async def get_home(
    q: GenericQuery[Foo | None] = None,
    foo: GenericQuery[list[Foo] | None] = None,
    bar: GenericQuery[list[Foo] | None] = None,
) -> dict[str, GenericQuery[list[Foo] | None] | GenericQuery[Foo | None]]:
    return {"q": q, "foo": foo, "bar": bar}
```

Hope this helps!
