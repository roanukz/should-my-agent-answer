```python
## Example 1 : pydantic model directly passed as an argument ##

@village_router.post(
    "/villages", response_model=VillageOut, response_model_exclude_none=True
)
async def village_create(
    village: VillageCreate,
    db: Session = Depends(get_db),
    current_user: User = Depends(get_current_active_user),
):
    """
    Create a new village
    """
    # Ensure the authenticated user is the owner
    village.owner_id = current_user.id

    try:
        new_village = create_user_village(db, village)
        return new_village
    except Exception as e:
        raise HTTPException(status_code=400, detail=str(e))


## Example 2 : build the pydantic object inside the router ##

@village_router.post(
    "/villages", response_model=VillageOut, response_model_exclude_none=True
)
async def village_create(
    village_name: str = Body(...),
    x_coordinate: int = Body(...),
    y_coordinate: int = Body(...),
    db: Session = Depends(get_db),
    current_user: User = Depends(get_current_active_user),
):

    village = VillageCreate(name=village_name, x=x_coordinate, y=y_coordinate)
    village.owner_id = current_user.id

    try:
        new_village = create_user_village(db, village)
        return new_village
    except Exception as e:
        raise HTTPException(status_code=400, detail=str(e))
```


### Description

I am quite new to API development and I am just wondering what is the best practice for my case or in general. I am trying to build a robust and well-written full stack app where my client is a react application but we may have more clients on the long run. 

I have 3 mains folders: routers, schemas and models. The router is the entry point of the API, schemas are my Pydantic model mostly used for validation and models my tables representations. 

I have one API endpoint, a POST endpoint to create a new village. To create a new village, we need to know 3 informations: village name, x and y coordinates.  

Should I pass directly a CreateVillage pydantic model as an argument to my router endpoint vs 3 individual parameters (name, x and y) and then build the CreateVillage object within the router method code? 


I am currently using the first method but when I am looking at my swagger, I don't see any arguments and everything is within the request body. If I use the second method, 3 clear input parameters will be showed on the swagger. 

What's the ideal practice?

## Accepted answer by Ale-Cas (NONE)

HI @Pierre-Alexandre35, 
The best practice for your case is to pass the model as an argument, like you're doing in "Example 1".

This is suggested in the docs https://fastapi.tiangolo.com/tutorial/body/#declare-it-as-a-parameter and you can see there the resulting swagger, too. 

See also this related linting rule: https://docs.astral.sh/ruff/rules/too-many-arguments/
