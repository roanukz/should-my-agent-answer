I am confident that this issue arises due to lazy loading of the field
`heroes: list["Hero"] = Relationship(back_populates="team")`
in the Team model, as it is included in the `TeamPublic` response model:
`heroes: list["HeroPublic"]`.

This issue does not occur in the synchronous version of SQLModel because there is no need to call await `db_team.awaitable_attrs.heroes` for lazy loading.

If I modify the `create_team` controller to explicitly call lazy loading with `await db_team.awaitable_attrs.heroes` before returning the Team model instance, everything works perfectly:

```
@app.post("/teams/")
async def create_team(*, session: AsyncSession = Depends(get_async_session), team: TeamCreate) -> TeamPublic:
    db_team = Team.model_validate(team)
    default_hero = Hero(team=db_team, name='Creator')

    session.add(default_hero)

    await session.commit()
    await session.refresh(db_team)
    
    await db_team.awaitable_attrs.heroes  # Here
    
    return db_team
```

Is it possible to integrate such lazy loading calls into the FastAPI framework? Manually handling lazy-loaded asynchronous attributes every time is inconvenient, and maintaining models with `AsyncAttrs` from SQLAlchemy becomes increasingly complex over time.

I created an example of such a fix; is it possible to add it to the FastAPI framework?

## Accepted answer by sehraramiz (NONE)

you can use ```sa_relationship_kwargs```:
```python
class TeamPublic(TeamBase):
      id: int

      heroes: list["HeroPublic"] = Relationship(sa_relationship_kwargs={"lazy": "selectin"})
```
you can use [other lazy options](https://docs.sqlalchemy.org/en/20/orm/relationship_api.html#sqlalchemy.orm.relationship.params.lazy)
it is not a fastapi problem, i think it is better to solve it on orm layer. maybe sqlmodel discussions is a better place to address this issue.
