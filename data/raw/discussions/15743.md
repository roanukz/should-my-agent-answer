### Description

I try to model a Html Form that has an optional email field.  

The intention is to have it  _either_ be absent _or_ validate with the properties set.

The pydantic model

```
class Ce(BaseModel): 
  x: EmailStr | None = Field(None, min_length=6)
```

works for manually instantiating a model, but fails when done via a HTML Form Post where the form has the email input not filled out.

It seems in this case, broswers send this datum as emty-string, such that _not_ providing an email tries to instantiate the model as if it would be `Ce(x="")`.


Can I remedy that _besides_ making `""` the default for the `EmailStr` field?
I wanto model an _optional_ email address.

## Accepted answer by strangeleo02 (NONE)

Because HTML browsers submit empty form inputs as an empty string (`""`) rather than omitting them or sending `null`, Pydantic attempts to validate `""` against your `EmailStr` and `min_length` constraints, resulting in a validation error.

The best solution is to use Pydantic's `BeforeValidator` to intercept the data *before* standard validation runs, converting any empty string into `None`.

If you apply constraints like `min_length` at the top level of the `Annotated` type (e.g. `Field(min_length=6)`), Pydantic will attempt to apply the constraint to `None` values as well. This leads to a `TypeError` (e.g., `object of type 'NoneType' has no len()`).

To prevent this, the constraint should be nested inside the `EmailStr` member of the Union type. This ensures that the length constraint is only evaluated when the value is a string.

### Solution using a nested reusable `Annotated` type

You can create a reusable pre-validator function and combine it with `Annotated` to define a custom type. This keeps your models clean and allows you to reuse the logic across multiple optional form fields.

```python
import sys
from typing import Annotated
import pytest
from fastapi import FastAPI, Form
from fastapi.testclient import TestClient
from pydantic import BaseModel, BeforeValidator, EmailStr, Field


# 1. Create a reusable function to transform empty strings to None
def empty_to_none(v: any) -> any:
    return None if v == "" else v


# 2. Define a reusable Annotated type
# The min_length constraint is nested specifically inside the EmailStr type definition
OptionalEmail = Annotated[
    Annotated[EmailStr, Field(min_length=6)] | None, BeforeValidator(empty_to_none)
]


class Ce(BaseModel):
    # Use your clean, reusable type here
    x: OptionalEmail = None


app = FastAPI()


# FastAPI automatically parses incoming form fields into the Pydantic model
@app.post("/post")
async def post(ce: Ce = Form()):
    return ce


# --- Test Suite ---

client = TestClient(app)


def test_write_noneok():
    # Case 1: Field is entirely absent from the form submission
    response = client.post("/post", data={})
    assert response.status_code == 200
    assert response.json() == {"x": None}


def test_write_emptyok():
    # Case 2: Field is present but empty (browser default behavior)
    response = client.post("/post", data={"x": ""})
    assert response.status_code == 200
    assert response.json() == {"x": None}


def test_write_valid_email():
    # Case 3: Field has valid data
    response = client.post("/post", data={"x": "user@example.com"})
    assert response.status_code == 200
    assert response.json() == {"x": "user@example.com"}


def test_write_invalid_email():
    # Case 4: Field has invalid data (fails min_length or EmailStr)
    response = client.post("/post", data={"x": "a@b"})
    assert response.status_code == 422  # Validation Error


if __name__ == "__main__":
    sys.exit(pytest.main([__file__]))
```
